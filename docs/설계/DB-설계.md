## 설계 원칙

이전 판에서 확정한 것 중 MVP에도 그대로 쓰는 것만 남긴다.

- **저장소**: 운영 데이터와 지도 레이어는 PostgreSQL + PostGIS. 래스터(DEM·연료 격자)와 ELMFIRE 입출력은 파일로 두고 DB에는 경로만. 근거 벡터 인덱스는 FAISS 파일
- **좌표계**: EPSG:5179(UTM-K) 하나로 저장, 지도로 보낼 때만 4326으로 변환
- **키**: 모든 테이블의 기본키는 `bigint` 대리키 `id`
- **이름**: 영어 snake_case, 테이블은 복수형, 시각은 `_at`(timestamptz)
- **상태값**: 값이 고정되면 ENUM, 계속 늘어나면 varchar
- **기록은 고치지 않고 추가**: 화선 정정·제안서 재생성은 새 행(새 버전). 이벤트 로그는 추가만
- **지역 독립**: 스키마에 특정 지역을 넣지 않음. 지역은 행정구역 코드로 데이터에서 구분

## 1. 기능 정리

### 1.1 기능 흐름

```
[입력]  ──▶  [핵심 ①] 예측  ──▶  [핵심 ②] 위험도  ──▶  [핵심 ③] 진화·대피 제안
보고·화선     P1~P8              P5 기준 R             규칙 판정 → 근거 → 제안서
                                                         │
                                         [제안 다루기] 근거 조회·질의·정정·이력
```

### 1.2 MVP 기능

| 묶음 | 기능 | F-ID | 하는 일 |
|---|---|---|---|
| **입력** | 산불 보고 | F-02, F-04 | 발화 위치·일시·신고 내용·신고자·기관별 접수 입력, 산불현황 조회 |
| | 실측 화선 보고 | F-02 | 1시간마다 화선 폴리곤(v1, v2 …), 잘못 보고하면 정정 |
| **핵심 ① 예측** | 확산 예측 실행 | F-09, F-05 | 최신 화선(없으면 발화점)과 기상으로 P1~P8 계산·지도 표시 |
| **핵심 ② 위험도** | 위험도 계산·조회 | F-10 | 예측마다 P5 범위의 23개 변수로 위험도 R 1개 |
| **핵심 ③ 제안** | 제안서 생성 | F-11, F-12, F-15~F-28 | 규칙 판정 → 근거 검색 → 진화 7·대피 7 항목 문장, 버전 `v화선.순번` |
| **제안 다루기** | 근거 조회 | F-13 | 문장의 근거 번호 → 매뉴얼 쪽·항목·요약 |
| | AI 질의응답 | F-29 | 근거 번호가 붙은 답변 |
| | 상황 정정 | F-30 | "괴산리 대피 완료, 헬기 2대 추가" → 확인 → 제안서 새 버전(예측은 그대로) |
| | 이력·변경 비교 | F-14 | 제안서 버전 목록, 직전 버전과 비교 |
| **마무리·공통** | 종료 처리 | F-03 | 종료 후 보고·예측·정정 차단 |
| | 로그인·권한 | F-01 | 통합지휘권자·열람자·상황 보고자·전산 관리자 |
| | 이벤트 로그 | F-32 | 누가 언제 무엇을 했는지 |
| **지도·자원** | 지도 레이어·주요 시설 | F-06, F-07 | 마을·시설·도로 표시 |
| | 진화자원 | F-08, F-31 | 상태(대기·투입·정비) 조회, 전산 관리자가 등록·수정 |

### 1.3 MVP 범위 결정

| # | 항목 | 결정 | 이유 |
|---|---|---|---|
| 1 | 산불 병합(P5가 겹치면 하나로) | **제외** | 10/13 회의에서 병합 장면을 뺐고 시연은 의성 한 건. 위험도는 산불별로 계산 |
| 2 | AI 질의응답 기록 | **질문·답변만 저장** | 답변에도 근거 번호가 붙고(F-13), 근거 부족을 기록해야 함(F-32) |
| 3 | 기관별 접수 기록 | **산불의 JSON 한 칸** | 화면 표시용이고 조회 조건으로 쓰지 않음 |
| 4 | 정정의 진화자원 투입 수("헬기 2대 추가") | **포함** (2026-10-23 팀장 결정) | 정정 가능 항목에 투입 수가 있고, S3(자원 배분) 판정의 입력. 자원 개별 상태(F-08·F-31, 전산 관리자 관리)와 별개로 **산불별 투입 수**로 관리 |

### 1.4 설계에 반영할 회의·데이터 결정

| 출처 | 결정 | DB 설계 영향 |
|---|---|---|
| 7주차-1차 회의 | 진화자원은 위치를 추적하지 않고 상태만, 진화대(인력)는 제외, 갱신은 전산 관리자 | 자원에 위치 없음. 개별 자원은 헬기·차량만 |
| 7주차-1차 회의 | 종료된 산불의 위험도는 표시하지 않음 | 종료 후 위험도 조회 불필요 |
| 6주차-2차 회의 | 취약계층은 합성 데이터, 고령자·유소년은 SGIS 실제 값 | 마을·인구에 실제 값과 가상값 구분 |
| 데이터 자원 D-02~D-05 | 행정경계·집계구·인구는 SGIS(전국, EPSG:5179), 마을은 법정리 단위이고 리별 인구는 법정동코드 10자리 | 행정구역은 SGIS 코드 기준, 마을은 법정동코드로 연결 |
| 7주차-1차 회의 | 위험도의 도로 접근성 변수 제외 | 위험도 계산에 도로 전체 좌표가 필수는 아님 |
