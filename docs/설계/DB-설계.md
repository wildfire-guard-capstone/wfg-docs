## 설계 원칙

이전 판에서 확정한 것 중 MVP에도 그대로 쓰는 것만 남긴다.

- **저장소**: 운영 데이터와 지도 레이어는 PostgreSQL + PostGIS. 래스터(DEM·연료 격자)와 ELMFIRE 입출력은 파일로 두고 DB에는 경로만. 근거 벡터 인덱스는 FAISS 파일
- **좌표계**: EPSG:5179(UTM-K) 하나로 저장, 지도로 보낼 때만 4326으로 변환
- **키**: 모든 테이블의 기본키는 `bigint` 대리키 `id`
- **이름**: 영어 snake_case, 테이블은 복수형, 시각은 `_at`(timestamptz)
- **상태값**: 값이 고정되면 ENUM, 계속 늘어나면 varchar
- **기록은 고치지 않고 추가**: 화선 정정·제안서 재생성은 새 행(새 버전). 이벤트 로그는 추가만
- **지역 독립**: 스키마에 특정 지역을 넣지 않음. 지역은 행정구역 코드로 데이터에서 구분

## 1. 기능 정리

### 1.1 기능 흐름

```
[입력]  ──▶  [핵심 ①] 예측  ──▶  [핵심 ②] 위험도  ──▶  [핵심 ③] 진화·대피 제안
보고·화선     P1~P8              P5 기준 R             규칙 판정 → 근거 → 제안서
                                                         │
                                         [제안 다루기] 근거 조회·질의·정정·이력
```

### 1.2 MVP 기능

| 묶음 | 기능 | F-ID | 하는 일 |
|---|---|---|---|
| **입력** | 산불 보고 | F-02, F-04 | 발화 위치·일시·신고 내용·신고자·기관별 접수 입력, 산불현황 조회 |
| | 실측 화선 보고 | F-02 | 1시간마다 화선 폴리곤(v1, v2 …), 잘못 보고하면 정정 |
| **핵심 ① 예측** | 확산 예측 실행 | F-09, F-05 | 최신 화선(없으면 발화점)과 기상으로 P1~P8 계산·지도 표시 |

### 1.3 MVP 범위 결정

| # | 항목 | 결정 | 이유 |
|---|---|---|---|
| 1 | 산불 병합(P5가 겹치면 하나로) | **제외** | 10/13 회의에서 병합 장면을 뺐고 시연은 의성 한 건. 위험도는 산불별로 계산 |
| 2 | AI 질의응답 기록 | **질문·답변만 저장** | 답변에도 근거 번호가 붙고(F-13), 근거 부족을 기록해야 함(F-32) |
| 3 | 기관별 접수 기록 | **산불의 JSON 한 칸** | 화면 표시용이고 조회 조건으로 쓰지 않음 |
| 4 | 정정의 진화자원 투입 수("헬기 2대 추가") | **포함** (2026-10-23 팀장 결정) | 정정 가능 항목에 투입 수가 있고, S3(자원 배분) 판정의 입력. 자원 개별 상태(F-08·F-31, 전산 관리자 관리)와 별개로 **산불별 투입 수**로 관리 |

### 1.4 설계에 반영할 회의·데이터 결정

| 출처 | 결정 | DB 설계 영향 |
|---|---|---|
| 7주차-1차 회의 | 진화자원은 위치를 추적하지 않고 상태만, 진화대(인력)는 제외, 갱신은 전산 관리자 | 자원에 위치 없음. 개별 자원은 헬기·차량만 |
| 7주차-1차 회의 | 종료된 산불의 위험도는 표시하지 않음 | 종료 후 위험도 조회 불필요 |
| 6주차-2차 회의 | 취약계층은 합성 데이터, 고령자·유소년은 SGIS 실제 값 | 마을·인구에 실제 값과 가상값 구분 |
| 데이터 자원 D-02~D-05 | 행정경계·집계구·인구는 SGIS(전국, EPSG:5179), 마을은 법정리 단위이고 리별 인구는 법정동코드 10자리 | 행정구역은 SGIS 코드 기준, 마을은 법정동코드로 연결 |
| 7주차-1차 회의 | 위험도의 도로 접근성 변수 제외 | 위험도 계산에 도로 전체 좌표가 필수는 아님 |

## 2. 테이블 정의

묶음 하나씩 정의한다. 표기: `NN` = NOT NULL, `PK`·`FK`·`UK` = 기본키·외래키·유일. 다른 묶음 테이블을 가리키는 FK는 그 묶음에서 테이블이 정해질 때 연결된다.

### 2.1 계정

#### `users` — 계정

사용자 한 명 = 1행. 전산 관리자가 발급하고 회원가입은 없다.

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | bigint | PK | |
| `login_id` | varchar(50) | NN, UK(대소문자 무시) | 로그인 아이디. 예: `cmd01` |
| `password_hash` | text | NN | 비밀번호 해시 |
| `name` | varchar(50) | NN | 이름 |
| `organization` | varchar(100) | NN | 소속 기관 |
| `role` | `user_role` ENUM | NN | `COMMANDER`(통합지휘권자)·`VIEWER`(열람자)·`REPORTER`(상황 보고자)·`ADMIN`(전산 관리자) |
| `admin_area_id` | bigint | FK → `admin_areas` | 관할 시군구. 전산 관리자만 NULL(전체) |
| `failed_login_count` | smallint | NN, 기본 0 | 연속 로그인 실패 횟수. **5 이상이면 잠김** |
| `created_at` | timestamptz | NN, 기본 now() | 발급 시각 |
| `updated_at` | timestamptz | NN, 기본 now() | 마지막 변경 시각 |
| `deleted_at` | timestamptz | | 회수·삭제 시각. **NULL이면 사용 중** |

- 로그인 거부: `deleted_at`이 있거나 `failed_login_count >= 5`
- 잠금 해제는 전산 관리자가 `failed_login_count = 0`으로
- 회수·삭제는 행을 지우지 않고 `deleted_at`만 기록(이벤트 로그·산불이 계정을 가리킴)
- 관할의 마지막 통합지휘권자는 회수·권한 변경 불가
- API 요청마다 `users` 행을 읽어 권한·회수 여부를 확인(JWT만 쓰고 세션 테이블은 두지 않음)

#### `event_logs` — 이벤트 로그

**누가, 언제, 어느 산불에서, 무엇을 했는지** 1건 = 1행. **추가만** 한다(수정·삭제 권한 회수). 화면에 보이는 구분·문장은 저장하지 않고 조회할 때 `action`·`details`로 만든다.

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | bigint | PK | |
| `created_at` | timestamptz | NN, 기본 now() | 언제 |
| `user_id` | bigint | FK → `users` | 누가. 시스템 이벤트는 NULL |
| `incident_id` | bigint | FK → `incidents` | 어느 산불. 로그인·계정 관리는 NULL |
| `action` | varchar(50) | NN | 무엇을. 예: `LOGIN_FAILED`, `PERIMETER_REPORTED`, `PROPOSAL_CREATED`, `ITEM_NO_EVIDENCE` |
| `details` | jsonb | | 세부 사실(대상 id, 버전, 변경 전후 값). **개인정보는 넣지 않음** |

### 2.2 산불·보고

상황 보고자는 지도에 **발화 지점을 점 하나로 찍고**, 이후 점을 여러 개 찍어 **산불 범위를 폴리곤으로** 그린다. 점은 `incidents`, 폴리곤은 `fire_perimeters`에 저장한다. 첫 보고에서 점만 찍고 폴리곤은 나중에 그려도 되고(초기대응), 둘을 같이 보고해도 된다.

#### `incidents` — 산불 사건

**어떤 테이블**: 산불 하나 = 1행. 보고 내용·진행상태·**현재 상황**을 담는다. 산불명과 주소는 따로 입력받지 않고 발화 지점의 행정구역과 날짜로 만들어 보여 준다(예: 「의성군 안평면 산불 (2025-03-22)」).

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | bigint | PK | |
| `ignition_point` | geometry(Point, 5179) | NN | 발화 지점. 보고자가 지도에 찍음 |
| `admin_area_id` | bigint | NN, FK → `admin_areas` | 발화 지점이 속한 **읍면동**(저장 시 자동 계산). 상위 시군구가 관할 |
| `started_at` | timestamptz | | 발생 일시(선택) |
| `reported_at` | timestamptz | NN | 신고 접수 일시 |
| `report_text` | text | | 신고 내용 |
| `reporter_org` | varchar(100) | | 신고 기관명(선택) |
| `reporter_name` | varchar(50) | | 신고자 성명(선택) |
| `reporter_phone` | varchar(20) | | 신고자 연락처(선택) |
| `intake_records` | jsonb | | 기관별 접수 기록 `[{"org", "received_at", "channel"}]`(선택) |
| `status` | `incident_status` ENUM | NN, 기본 `RECEIVED` | `RECEIVED`(접수)·`IN_PROGRESS`(진행 중)·`ENDED`(종료) |
| `official_stage` | `response_stage` ENUM | NN, 기본 `INITIAL` | 공식 대응단계: `INITIAL`(초기대응)·`STAGE1`·`STAGE2`(확산대응 1·2단계) |
| `alert_level` | `alert_level` ENUM | NN, 기본 `ATTENTION` | 위기경보: `ATTENTION`(관심)·`CAUTION`(주의)·`ALERT`(경계)·`SERIOUS`(심각) |
| `situation` | jsonb | NN, 기본 `{}` | **현재 상황**(아래). 상황 정정으로 바뀜 |
| `reported_by` | bigint | NN, FK → `users` | 최초 보고자 |
| `created_at` | timestamptz | NN, 기본 now() | 등록 시각 |
| `ended_at` | timestamptz | | 종료 시각 |
| `ended_by` | bigint | FK → `users` | 종료 처리자 |

`situation` 형태 — 마을 키는 `villages.id`:

```json
{
  "villages": { "1024": { "evacuated": true, "evac_order": true, "injured_or_isolated": 0 } },
  "deployed": { "helicopter": 6, "fire_truck": 12, "crew": 80 },
  "expected_hours": 5,
  "disaster_sms_sent": true
}
```

**데이터가 쌓이는 방식**

- 새 산불 보고 → 1행 INSERT(`RECEIVED`)
- 첫 실측 화선이 들어오면 → `status = IN_PROGRESS`
- 상황 정정을 확인하면 → `official_stage`·`alert_level`·`situation` UPDATE(정정 이력은 `situation_corrections`에 쌓임)
- 종료 → `status = ENDED`, `ended_at`·`ended_by`
- 삭제하지 않는다. 산불 하나당 행은 계속 1개

**기능에서 쓰이는 곳**

| 기능 | 사용 |
|---|---|
| F-02 산불 보고 | INSERT |
| F-04 산불현황 | 발생·신고·신고자·접수 기록·진행상태·공식 단계 읽기 |
| F-05 지도 | 발화 지점 표시 |
| F-09 예측 | 화선이 없으면 발화 지점에서 시작 |
| F-11·F-15 제안 | 공식 단계와 판정 단계 비교(격상 권고), `situation`을 규칙 판정 입력으로 |
| F-30 정정 | `official_stage`·`alert_level`·`situation` UPDATE |
| F-03 종료 | `status`. 이후 보고·예측·정정 차단의 기준 |

#### `fire_perimeters` — 실측 화선

**어떤 테이블**: 상황 보고자가 점을 이어 그린 **산불 범위 1건 = 1행**. 찍은 점들은 폴리곤 하나로 저장한다.

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | bigint | PK | |
| `incident_id` | bigint | NN, FK → `incidents` | |
| `version_no` | int | NN | 화선 버전 v1, v2 … |
| `geom` | geometry(MultiPolygon, 5179) | NN | 실측 연소 범위 |
| `observed_at` | timestamptz | NN | 관측 시각 |
| `reported_by` | bigint | NN, FK → `users` | 보고자 |
| `created_at` | timestamptz | NN, 기본 now() | 등록 시각 |
| `corrected_at` | timestamptz | | 정정된 시각. NULL이면 유효 |

- 유일: `(incident_id, version_no) WHERE corrected_at IS NULL` — 한 버전에 유효한 화선은 하나
- 면적(ha)은 저장하지 않고 `ST_Area`로 계산

**데이터가 쌓이는 방식**

- 새 보고 → 다음 번호로 1행 INSERT. 1시간마다 보고하므로 8시간이면 산불 하나에 약 8행
- 정정 → 기존 행에 `corrected_at` 기록 + **같은 버전 번호로 새 행** INSERT. 원래 행은 남김

**기능에서 쓰이는 곳**

| 기능 | 사용 |
|---|---|
| F-02 화선 보고·정정 | INSERT, 정정 시 `corrected_at` |
| F-05 지도 | 최신 유효 화선·이전 버전 표시 |
| F-04 산불현황 | 최신 화선 버전·면적 |
| F-09 예측 | 최신 유효 화선을 시작점으로 |
| 「재예측 필요」 | 최신 화선 버전 > 마지막 예측의 기준 화선 버전이면 표시 |
| F-11 제안서 버전 | `v(화선 버전).(순번)`의 앞 번호 |
