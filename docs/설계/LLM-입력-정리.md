# LLM 입력 정리

대응 제안 생성 에이전트와 AI 어시스턴트의 LLM(EXAONE)이 받는 정보를 정리합니다. 정보마다 누가 만드는지, 규칙 엔진이 어떻게 판정하는지, 어떤 데이터가 더 필요한지를 적었습니다. LLM 입력과 관련된 내용은 이 문서에서 계속 관리합니다.

## 원칙

- **수치와 판정은 규칙 엔진만 만듭니다.** 규칙 엔진은 항목마다 판정 줄(`finding`), 수치 목록(`facts`), 대상, 구분(즉시·대기·협의·요청), 비우는 칸(`withheld`), 판정 근거 청크(`rule_basis`)를 넘깁니다. 이 값은 `proposal_items.detail`에도 그대로 저장됩니다.
- **LLM은 받은 값으로 문장만 씁니다.** 문장에 쓸 수 있는 숫자는 판정 줄, `facts`, 함께 받은 근거 청크에 있는 것뿐입니다.
- **근거 기준이 없는 칸은 비웁니다.** 「근거가 부족하여 표시하지 않았습니다」로 표시하고 이벤트 로그에 남깁니다.

**만드는 곳**
- `규칙 엔진`: 계산·판정합니다.
- `DB`: 저장된 값을 그대로 넘깁니다.
- `근거 검색`: KURE-v1과 FAISS로 근거 청크를 찾습니다.
- `고정값`: 코드에 둡니다.
- `입력`: 사용자가 넣습니다.

**상태**: ✅ 확보·바로 계산 가능 · 🟡 일부·대체값·규칙 미정 · ❌ 미확보 · ❓ 출처 확인 필요 · ➖ 제외

**모은 데이터로 만들 수 있나**(오른쪽 끝 칸, 황승준): 한 행씩 같이 확인하면서 채움. ✅ 지금 모은 데이터·입력·계산으로 만들 수 있음 · 🟡 일부만 됨(안 되는 부분을 함께 적음) · ✗ 못 만들거나 애매함(이유를 함께 적음) · — 제외 항목. 빈칸은 아직 확인 전. 계산·판정 방법은 [`규칙-엔진-설계.md`](규칙-엔진-설계.md)에 정리

**근거 표기**
- 백틱 안의 코드(예: `DEC-FDPA-t3-p1`)는 근거 코퍼스의 청크 ID입니다.
- 「표준매뉴얼 p.NN」은 아직 청킹하지 않은 표준매뉴얼 쪽 번호입니다(프로토타입 근거 키 `SM-pNNN`).

## 추가로 찾아야 할 데이터

표에서 ❌·❓인 것만, 급한 순서로 모았습니다.

1. **마을 기준점(L-12 · D-06·D-07)** — 대피 항목 E1~E7과 S2·S3·S5의 마을 판정이 모두 여기에 막혀 있습니다.
2. **건물(주택) 자료(L-18)** — 데이터-자원 표에 아직 없는 새 항목입니다. S1 시설피해(20동)와 S5에 필요합니다. 후보는 도로명주소 건물 DB와 국토교통부 GIS건물통합정보입니다.
3. **대피소(L-23 · D-09)·취약시설(L-19 · D-10)** — E3·E4에 필요합니다.
4. **헬기 운항 제한 기준(S4)** — 데이터가 아니라 근거 문서입니다. 법령·규정 36건에는 풍속·시정 기준이 없습니다.
5. **지정 대피로·진화차량 진입로(E5 · D-16·D-17)** — 출처가 없으면 E5 판정 방식을 바꿔야 합니다.
6. **송전시설(L-21 · D-14)·국가유산(L-20 · D-13)·소방서(E7 · D-11)·유관기관(S6 · D-12)**
7. **표준매뉴얼 청크(L-11)** — 데이터는 있지만 청킹 전입니다. S2·S3·S5·E2·E4·E6의 규칙 근거가 p.65·72~79에 있습니다.
