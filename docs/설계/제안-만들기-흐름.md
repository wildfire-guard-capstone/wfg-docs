## 2. 누가 무엇을 — 엔진 설계의 기준점

### 2-1. 한 줄

- **규칙 엔진 = 진단서** — 이 산불이 지금 **어떤 상태이고 무엇이 가능한지**
- **LLM = 처방** — 진단서를 보고 매뉴얼 근거로 **무엇을 하라**
- **사람 = 결정** — 실제로 할지 말지

### 2-2. 누가 하나 — 이 순서로 묻는다

```
규칙(조건 · 숫자 · 정렬 키)으로 미리 적을 수 있나?
 ├─ 예 → 엔진 (기준 등급을 붙인다)
 └─ 아니요 → 매뉴얼 문장을 읽고 조치를 고르는 일인가?
             ├─ 예 → LLM
             └─ 아니요 → withheld (아무도 판단하지 않음)
```

- **근거가 약하다고 LLM에 넘기지 않는다** — 넘기면 가정이 사라지지 않고 숨을 뿐이다. 엔진이 하고 ⚠로 드러낸다

| 줄 세우기 — 값 하나로, 동률이면 기본값 | 도달 빠른 순 → (동률) 고령자 많은 순 ⚠ |
| 묶기 — 항목마다 필요한 값만 | status · 구분 · finding · facts · withheld · rule_basis · targets |

### 2-4. 기준 등급 — 엔진 규칙마다 붙인다

- 등급은 **기준(판정 · 자격 · 줄 세우기 키)**에만 붙인다. 찾기 · 재기 같은 **계산 값(14:55 도달 · 42 ha)에는 붙이지 않는다**. 단, 「무엇으로 줄 세울지」를 고르는 것은 기준이라 등급을 붙인다

| 등급             | 기준의 출처                                        | 엔진                                                 |
| -------------- | --------------------------------------------- | -------------------------------------------------- |
| **A** 원문 수치    | 매뉴얼 · 법령 · 고시에 숫자까지 (10 ha · 5시간 · 50 km)     | 판정                                                 |
| **B** 원칙 + 해석  | 원칙은 있고 적용은 우리 해석 (「과」 → 가장 높은 기준 · 5시간을 대피소에) | 판정 + ⚠ 해석 표시                                       |
| **C** 사례       | 백서 · 해외 지침 (내 리 + 옆 리 → 읍면 거점)                | 판정 + 사례 출처                                         |
| **D** 우리가 정한 값 | 근거 없이 꼭 필요해서 정함 (1 km 거리대 · 동률 처리)            | **출력에 꼭 필요할 때만** 기본값 · ⚠ 설계 변수 · 선택지를 지우는 데는 쓰지 않음 |
| **E** 없음       | 기준도 데이터도 없음 (헬기 운항 풍속 · 추가 투입 대수)             | `withheld`                                         |

### 2-5. 판정하되 숨기지 않는다

1. **원래 값과 판정을 함께** — 「2단계」만이 아니라 「면적 초기 · 풍속 1단계 · 시설 2단계 → 2단계(시설 46동)」
2. **거른 것도 이유와 함께** — 「안평초교: 5시간 안 도달로 제외」
3. **해석 등급을 드러낸다** — B · C · D 판정은 판정 이유에 「해석」 · 「설계 기본값」으로 표시
- 판정 ≠ 결정 — 「1단계 기준에 해당」까지가 엔진, 「1단계 발령」은 사람

### 2-6. LLM · 프롬프트 조립

- **LLM**: 검색된 매뉴얼에서 조치를 고르고 → 엔진 값(대상 · 시점)을 붙여 문장을 쓰고 → 근거 [k]를 단다. 강조는 바꿀 수 있지만 **숫자 · 판정 · 순서는 바꾸지 않는다**. `withheld`는 「근거가 부족하다」고 쓴다
- **프롬프트 조립**(김지오 파이프라인): 엔진 JSON + 근거 검색 → 지시문, LLM 문장 뒤 숫자 · 인용 검사. 값은 바꾸지 않는다
- **「LLM 후보」** = D등급 중 여러 값을 저울질하는 순서. LLM이 더 잘하는지 **시험할 대상**이지, 넘긴다는 뜻이 아니다

### 5-5. E4 대피소 (11/4)

> **범위**: E4 = 대피해야 하는 마을마다 ① **갈 수 있는 대피소 후보**를 골라 보여 주고, ② 후보가 없으면 **「대피소를 정해야 한다」**를 알린다. 몇 명을 어디로 보낼지(배정)는 하지 않는다 — 최종 선택은 지휘권자

**1. 결정 질문** — 대피하는 마을 주민을 **어디로** 보낼까?
- ① 이 마을이 **갈 수 있는 안전한 대피소**는 어디인가?
- ② 갈 수 있는 곳이 없다면 → **대피소를 어디로 정할까?**

**5. 어떻게 고르나 · 등급**

후보를 고르는 과정은 **① 모으기(R-09) → ② 위험한 곳 빼기(R-10) → ③ 순서(R-11)**, 그래도 없으면 **④ 결정 필요(R-12)**

**① 모으기 (R-09)** — 대피소를 **마을 시설**(경로당 · 마을회관 등, 급히 모이는 곳)과 **거점 시설**(학교 · 체육관 · 공공 · 복지시설, 여러 마을이 머무는 곳)로 나누고, 종류마다 **R-10을 통과한 대피소 중 마을에서 가까운 2곳**을 후보로 모은다. 리 · 읍면 · 시군 경계는 따지지 않고 **거리만** 본다
- 마을 단위로 만든다 ← [매] p.66 행정리별 · [실] 마을별 사전 선정 (**A**)
- 두 종류로 나눈다 ← [매] p.79 「마을회관, 학교 등」 · [의] 긴급 대피 · 집결용과 체류용의 위계 (**B**)
- 가까운 2곳 ← [구] 「최단거리」 · [실] 「1, 2후보지」 (**B**)
- 경계로 자르지 않는다 ← [매] p.76 상호 대피소 사용 · [의] 정적 지표 의존 비판 (**A + C**)

**② 위험한 곳 빼기 (R-10)** — **대피소 건물 자리**에 불이 닿는 시간으로 판정한다. **5시간 안이면 뺀다(예외 없음). 8시간 안이면 원칙적으로 빼되, 그 종류에 안전한 곳이 하나도 없을 때만 「예외 후보」로 남긴다.** 8시간 안에 닿지 않으면 안전. 마을이 위험구역이어도 대피소 자리가 안전하면 후보다
- 5시간 안 제외 ← [매] p.75 5시간 안 = 주민이 모두 떠나야 하는 위험구역 (**A**)
- 8시간 안 원칙 제외 ← [구] 재해위험 지역 시설은 원칙 제외 · [매] p.75 8시간 안 = 잠재 위험구역 · [의] 대피장소 영향은 발송 5~10시간 뒤 (**A + C**)
- 안전한 곳이 없을 때만 예외 ← [구] 단서 「대체 가능 시설이 없는 경우 지정 가능」 (**A**)
- 대피소 자리로 판정 ← [매] p.79 대피는 「안전한 대피장소로」, 대표 예가 마을 안 마을회관 (**B**)

**③ 순서 (R-11)** — 안전 후보 → 예외 후보, 그 안에서 **마을에서 가까운 순**. 수용 인원은 순서에 쓰지 않고 정보로만 보여 준다
- 안전 → 예외 ← [구] 예외는 대안이 없을 때만 (**A**)
- 가까운 순 ← [구] 「최단거리」 (**B**)

**④ 결정 필요 (R-12)** — 두 종류 모두 쓸 수 있는 대피소가 없으면 「이 마을은 대피소를 정해야 합니다」 ← [매] p.66 대피장소는 행정리별로 미리 정해 두게 되어 있음 → 없으면 지금 정해야 함

**우리가 정한 값(설계 변수)** — 종류마다 「2곳」([실] 1 · 2후보지를 빌림) · 시설 나누기(모텔 제외, 휴양마을 · 면사무소 = 거점) · 거리 = 직선거리(나중에 도로 거리) · 8시간 선 바로 바깥의 여유 거리는 두지 않음([의]의 500 m · 1 km는 검증 안 된 값)

### 5-7. E6 재난문자 · 방송 전파 (11/5)

> **범위**: E6 = 불이 닿을 마을이 있는 **읍면마다 Set / Go 단계를 판정**하고, 직전 제안서보다 **단계가 바뀐 읍면을 표시**해 재난문자 · 방송 송출을 제안한다. **문안은 쓰지 않는다** — Go 문자에 들어갈 대피소는 사람이 E4 후보 중에서 정한다

**1. 결정 질문** — 어느 지역(읍면)에, 어떤 단계(Set · Go)의 재난문자 · 방송 송출을 요청할까?

**2. 매뉴얼 · 근거가 하라는 것** ([매] = 표준매뉴얼(2026.6), [백] = 2025 의성산불백서)

**3. 엔진 / LLM 일 나누기**

| 엔진 (진단 = 어느 읍면이 어느 단계인가, 무엇이 바뀌었나) | LLM (처방 = 어디에 송출하라) |
|---|---|
| 읍면마다 Go / Set 판정, 해당 마을을 붙인다 | 「단계가 바뀐 ○○면에 Go(또는 Set) 단계 재난문자(CBS) · 자막방송(DITS) 송출을 요청하고 마을방송 등도 함께 쓰라」(p.76 · p.78) |
| 직전 제안서와 비교해 단계 변화(새로 / 올라감 / 그대로)를 붙인다 | 「Go 문자에는 대피 장소가 들어가야 하니 대피소를 먼저 정하라」(p.76). 근거 [k]를 단다 |

- 사람(결정): 대피소 결정, 문자 내용 작성 · 송출
- 하지 않는 것: 문안 쓰기 · 대피소 고르기 · Ready(산불 발생) 문자 · 해제 문자

| ③ 투입 · 부를 수 있음 | 투입 = 이 산불에 연결된 자원 / 부를 수 있음 = `status` 대기 + 범위 안 | 계산 |
| ④ 가까운 순 | 기지를 발화점에서 가까운 순으로 보여 줌(거리 값도 함께). 판단이 아니라 보여 주는 순서 | **B** ([고] 비고 ② 「가까운 기관」) |

| status | `scope_expands`: 5시간 뒤 범위가 넓어짐 / `available_in_scope`: 범위 안에 부를 수 있는 자원 있음 / `none_in_scope`: 범위 안에 부를 수 있는 자원 없음. **늘 만든다** |
| 구분 (B) | 「할 수 있는 일」의 종류: 관할에 부를 수 있는 자원 → **즉시**(바로 쓸 수 있음) · 범위 안 응원 자원 → **요청** · `scope_expands` → **대기** · `none_in_scope` → **협의**(범위 밖은 상위 단계 발령 · 산림청장 동원 요청 필요). 함께 맞으면 모두 붙임 |

| rule_basis | `NOTI-MOBL-t0-p2` · `SM-p077` · `SM-p078` |
| targets | 기지 id |
