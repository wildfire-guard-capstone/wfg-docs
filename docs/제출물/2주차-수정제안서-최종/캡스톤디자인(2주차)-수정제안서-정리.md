### 한 단락 요약(원본 내용만으로)

국내 산불은 발생 건수는 줄지만 단일 사건 피해가 커지는 구조로 바뀌었고(2025년 459건, 피해 105,099ha, 영남권 산불 사망 27명·재산피해 약 1조 818억 원), 확산 예측 기술(국립산림과학원 산불확산예측시스템)과 대응 규칙(산림재난방지법 시행령 대응 단계, 법 제34조 통합지휘, 실무매뉴얼)은 이미 있으나 **예측을 역할별 대응 행동으로 옮기는 연결고리가 소수 인력의 수작업에 묶여 있다**. 본 과제는 발화점 또는 화선 위치만으로 (1) 물리 기반 확산 모델 **ELMFIRE**로 확산 방향·속도·도달 시각을 산출하고 AI Hub 저작도구의 위험도 기준(25변수 가중합)을 이식해 조건위험도(0~100)를 계산하는 예측 엔진, (2) 소방요원(FF)·구조요원(RW)·공무원(GO) 3역할의 임무를 **KURE-v1 + BM25 하이브리드 검색과 EXAONE 4.0 32B** 기반 RAG로 생성하되 문장마다 법령·매뉴얼 조항을 각주로 달고 근거 5개 미만이면 「근거 부족」을 표시하며 활성화 기관·대응 단계는 규칙으로 고정하는 임무 생성 모듈, (3) 예측과 임무를 한 화면에 보이는 React·MapLibre GL 대시보드를 개발한다. AI Hub 데이터(실제 산불 101건)는 시계열 확산 이력이 없고 위험도 라벨이 조건과 무관(기준 일치 4.7%, r=0.059)하여 "학습용"이 아닌 "보정·계승용"으로만 쓰고, 평가는 IoU(≥0.5)·Recall@5(≥0.80)·RAGAS 근거 충실도(≥0.90)·답변 관련성(≥0.80)을 hold-out 사건으로 자동 채점한다. 개발환경은 RTX A6000 48GB GPU 서버 1대 + AWS 서비스 서버 + Linux 개발 PC이며, 18개 개발 항목을 2~16주차 간트로 배정하고 Confluence·Jira·Google Drive·GitHub Organization·주 2회 대면 회의·Discord로 협업한다.

## 1. 개발 배경 및 중요성

### 1.1 산불 피해 규모의 구조적 변화

- "국내 산불은 발생 건수보다 단일 사건의 피해 규모가 커지는 방향으로 바뀌고 있다."
- 2025년 산불은 **459건**으로 최근 10년 연평균(**529건**)보다 적었으나, 피해 면적은 **105,099ha**로 연평균의 **약 7.3배**.[1]
- 3월 경북 의성에서 시작된 영남권 산불은 안동·청송·영양·영덕으로 번지며 **사망 27명, 재산피해 약 1조 818억 원**.[2]
- "문제는 '얼마나 자주 발생하는가'에서 '발생한 산불이 얼마나 커지는가'로 옮겨 갔고, 커진 산불일수록 대응 판단의 속도가 피해를 좌우한다."

### 1.2 예측과 대응 사이의 자동 연결고리 부재

- 화선 탐지·확산 예측 기술은 이미 있다. 국립산림과학원 산불확산예측시스템은 시간대별 확산 속도·방향과 주요 시설 도달 시간을 산출한다.[3]
- "비어 있는 것은 그다음이다. 그 예측을 '지금 누구를 먼저 대피시키고 어느 진입로를 쓸 것인가'라는 행동 지시로 이어 주는 단계다." 화선 탐지→확산 예측→대피 권역 설정이 하나의 흐름으로 자동 연결되어야 한다는 지적이 2025년 영남권 산불 이후 제기되었다.[3]
- 지금 이 연결 작업은 **소수 인력의 수작업**에 의존한다. 산불 확산을 실시간 분석해 현장에 제공하는 조직은 극소수 인력으로 운영되어 장시간 대형산불에 대응하기 어렵다.[3]
- 세 가지 한계: 확산 속도가 대응 속도를 앞섬 / 진압·구조·행정 등 주체에 따라 필요한 임무가 갈림 / "확산이 빠를수록 갱신할 판단이 늘고, 산불이 길수록 그 작업이 누적되며, 주체가 다양할수록 임무 할당이 번거로워진다." → 인력을 늘리는 방식으로는 해결할 수 없다.
- 따라서 본 과제는 부재하는 연결고리를 자동화한다. "확산 예측에서 역할별 임무 부여까지를 사람 개입 없이 이어, 사람 손에서 끊기던 고리를 잇는다. 다만 현장 지휘 권한을 대체하지는 않고, 모든 판단 근거를 확인할 수 있는 형태로 제시하는 보조 도구로 시스템을 설계한다."

## 2. 개발 목표

1장의 두 공백 — **"확산 예측과 대응 행동이 자동으로 연결되지 않는 문제와 그 연결이 소수 인력의 수작업에 묶여 있는 문제"** — 를, 발화점 또는 현재 화선 위치만으로 **확산 예측부터 역할별 대응 임무 생성, 한 화면 표출까지를 사람 개입 없이 자동으로 잇는** 시스템으로 해소한다. 자동 생성이 만드는 근거 없는 서술은 문장마다 근거 조항을 부기하고 「근거 부족」을 표시하는 근거 검증으로 통제한다. 세부 목표는 셋이다.

### 2.1 좌표 기반 확산·위험도 예측 엔진

- 입력: 발화점 또는 진행 중인 화선 위치(점 또는 폴리곤).
- 주변의 지형·연료·기상·인프라 조건을 **격자 단위로 자동 구성**.
- 물리 기반 확산 모델이 시간에 따른 **확산 방향·속도와 화선 도달 시각**을 산출.
- 발화 환경의 **위험도를 정량화**하고 어느 요인(기상·지형·연료·인프라)이 위험을 끌어올렸는지 함께 제시.

### 2.2 역할별 대응 임무 자동 생성과 근거 검증

- 예측 결과를 입력받아 **소방·구조·행정** 각 역할이 지금 수행해야 할 임무를 자동 작성. 역할별로 구분해 생성.
- 각 대응 임무를 **검색 증강 생성(RAG)**으로 관련 법령·매뉴얼 원문을 찾아 **문장마다 근거 조항**을 달아 제시.
- 검증 규칙(원문):
  - 검색된 근거가 **5개 미만이면 「근거 부족」**으로 표시.
  - **활성화 기관과 대응 단계는 규칙으로 고정**하여 LLM의 판단을 배제.
  - 근거를 찾지 못한 문장은 임의로 삭제하지 않고 「근거 부족」으로 표시하여 "시스템이 확인하지 못한 범위까지 함께 드러낸다."
- "이 근거 검증은 RAG 검색 결과에 직접 붙는 단계이므로 별도 계층이 아니라 임무 생성 모듈의 일부로 둔다."

### 2.3 예측과 대응의 단일 화면 표출

- 확산 예측 결과(위험도·확산 방향·화선 도달 시각)와 자동 생성된 역할별 대응 임무를 **하나의 화면**에 표출하는 대시보드.
- 지도 위에 상황을 겹쳐 보여주고 그 옆에 근거 조항이 붙은 역할별 임무를 배치. 소방·구조·행정 각 역할에 맞춰 정보의 깊이와 행동 지침을 달리 제시.

## 3. 차별성

### 3.1 현행 산불 대응 체계

"우리나라 산불 대응은 예방부터 대응까지 단계별로 국가 시스템을 이미 갖추고 있다."

**[표 3-1] 현행 국가 산불 시스템**

| 단계 | 시스템 | 기능 |
|:--:|---|---|
| 예방(발화 전) | 국가산불위험예보시스템[4] | 산불위험지수 예보(100m 격자, 시군구 단위 1시간 간격) |
| 상황 파악 | 국가산불정보시스템[5] | 실시간 산불 위치·현황 모니터링 |
| 확산 예측(발화 후) | 산불확산예측시스템(국립산림과학원)[3] | 시간대별 확산 속도·방향, 주요 시설 도달 시간 |

- 대응 규칙도 이미 문서로 존재: 「산림재난방지법 시행령」은 면적·풍속·진화예상시간을 기준으로 **초기대응(10ha 미만)·확산대응 1단계(10ha 이상 100ha 미만)·확산대응 2단계(100ha 이상)**를 구분하고, 지자체 대응 범위를 넘어서면 **시·도지사 또는 산림청장이 통합 지휘**(「산림재난방지법」 제34조).[6] 각 단계에서 어떤 기관이 무슨 임무를 맡는지는 산불재난 위기대응 실무매뉴얼에 표로 규정.[7]
- "비어 있는 것은 예측도, 규칙도 아니다. 그 예측을 실시간으로 규칙에 적용해 '지금 이 역할이 할 구체적 행동'으로 옮기는 단계다." 이 변환은 소수 전문 인력의 수작업에 의존.[3] 2025년 3월 영남권 산불에서 위험 예보는 적중했으나 이 수작업이 확산 속도를 따라가지 못했다.[3]
- 정부는 2026년 'AI 기반 산불·연무 확산 예측' 사업에 착수(확산 방향·속도 예측, 주민 대피 경로와 진화 인력·장비 투입 경로 제시).[8] "다만 이 사업의 목표는 예측과 경로 산출로 현장 판단을 지원하는 데 있고, 역할별 대응 임무를 근거와 함께 생성하는 단계는 포함하지 않는다."

### 3.2 본 과제의 차별점

"본 과제는 예측 기술을 새로 제안하지 않는다. 예측에 뒤따르는 대응 판단을 사람 대신 자동으로 만들고, 그 과정에서 생기는 위험을 통제하는 데 차별점이 있다."

- **첫째, 역할별 대응 판단의 자동 생성.** 소수 인력이 회차별로 손수 만드는 대응 전략을, 예측 결과로부터 소방·구조·행정 각 역할의 임무로 나누어 자동 생성.
- **둘째, 근거 추적과 검증.** 기존 발행물에는 근거 조항 표기가 없고 범용 LLM은 근거 자체가 없다. 모든 대응 문장에 법령·매뉴얼 조항을 근거로 달고[9], 근거 5개 미만 답변은 「근거 부족」 표시, 활성화 기관·대응 단계는 규칙으로 고정해 LLM 판단 배제.

**[표 3-2] 기존 국가 시스템 · 범용 LLM · 본 과제 비교**

| 항목 | 기존 국가 시스템 | 범용 LLM 질의응답 | 본 과제 |
|:--:|---|---|---|
| 대응 문장 생성 | 회차별 발행(수작업) | 자동 · 근거 없음 | 자동 · 근거 대조 |
| 역할별 산출 | 발행물당 진화·대피 2종 | 구분 없음 | 역할별 |
| 근거 추적 | 조항 표기 없음 | 불가 | 조·항 단위 |
| 생성문 검증 | 표기 없음 | 없음 | 근거 부기 + 규칙 판정 |

## 5. 개발 방법 및 체계

### 5.1 전체 시스템 아키텍처

[그림 5-1: 시스템 개요도] — 제목 "WILDFIRE RESPONSE AI SYSTEM ARCHITECTURE". 인터페이스(Client UI)·서버(Application Server)·데이터(Data) 세 계층을 상·중·하로 배치하고, 요청·응답 흐름을 ①~⑨ 번호로 표시한 도식. 그림이 담은 정보는 다음과 같다.

- **인터페이스 계층(Client UI)**: 「사용자(현장 역할)」 박스에 역할 칩 FF·RW·GO. 「웹 대시보드」(React · MapLibre GL · GeoJSON 레이어)에 하위 칩 「확산 예측 지도」「위험도」「역할별 보고서」. 대시보드는 ⑨로 「확산 폴리곤·위험도」(GeoJSON·JSON)와 「역할별 대응 보고서」(현장 분석·임무·각주)를 받아 표시.
- **서버 계층(Application Server)** — 처리 순서:
  - ① 요청 → 「API 서버·상황 구성」(요청 수신·기상 결합, **FastAPI**)
  - ② → 「① 산불 예측 모델」 묶음: 「확산 예측」(레벨셋 확산 시뮬레이션, **ELMFIRE**) ③→ 「위험도 판정」(조건위험도 0~100, **Rule-Based**)
  - ④ → 「② 역할별 임무 생성 모델」 묶음: 「규칙 판정」(대응단계·활성 기관, **Rule-Based**) ⑤→ 「근거 검색」(벡터 + BM25 · Top-5, **KURE-v1 · BM25**) ⑥→ 「보고서 생성」(현장 분석·임무·인용, **EXAONE 4.0 32B**)
  - ⑦ → 「응답 조립」(GeoJSON·위험도·보고서, **REST API**) → ⑧ 응답 → 「역할별 대응 보고서」 → ⑨ 대시보드. 확산 예측·위험도 판정 결과는 「확산 폴리곤·위험도」로도 ⑨ 대시보드에 전달.
- **데이터 계층(Data · 실시간 수집 + 사전 구축)**:
  - 실시간 수집: 「기상 캐시」(풍속·풍향·습도) ← 외부 원천 「기상청 단기예보」(공공데이터 API). 기상은 API 서버로 조회(점선 "기상").
  - 사전 구축(배치 · 운영 전 1회 + 주기 갱신): 「공간 격자·행정경계·확산 파라미터 저장소」(PostGIS · GeoTIFF 30m 격자 · fuel_models.csv) ← 외부 원천 「공공데이터」(DEM·임상도·인프라, "격자 정합"), 「행정경계 GIS」(시·도/시·군·구, "적재"), 「AI Hub 소실 경계」("IoU 보정"). 저장소는 확산 예측에 "격자·연료 계수", 규칙 판정에 "행정경계"를 공급.
  - 「근거 색인」(KURE-v1 벡터 + BM25) ← 외부 원천 「법령·매뉴얼」("청킹·임베딩"). 근거 검색에 "근거 청크" 공급.
- **범례**: 검은 번호 화살표 = 요청·응답 흐름(①→⑨), 회색 점선 = 수집·사전 구축, 파란 점선 = 데이터 조회, 회색 점선 박스 = 외부 원천 데이터.

본문 설명(원문): 인터페이스는 사용자가 발화 위치·시각·역할을 입력하고 확산 예측 지도·위험도·역할별 보고서를 확인하는 웹 대시보드. 서버는 요청 1건을 산불 예측 모델(5.2.1)과 역할별 임무 생성 모델(5.2.2)로 **순차 처리**해 예측 결과와 대응 보고서를 반환. 데이터 계층은 실시간 수집 기상 자료와 운영 전에 구축해 두는 공간 격자·확산 파라미터·근거 색인을 서버에 공급.

### 5.2 핵심 모델

본 시스템은 발화 이후 **① 산불이 어떻게·얼마나 위험하게 번질지 예측하는 모델(5.2.1)**과 그 예측을 받아 **② 현장 역할별 대응 임무를 생성하는 모델(5.2.2)**로 구성. 각 모델은 4장의 데이터를 자신의 입력으로 구축하는 절차를 포함. "시스템의 중심은 **의사결정**이며, 예측 모델의 산출물이 그 안으로 들어가 역할별 행동으로 연결된다."

#### 5.2.1 산불 예측 모델

**확산 예측(ELMFIRE)**과 **위험도 판정** 두 부분. 4장 운영 입력을 30m 격자로 정합한 조건(기상·지형·연료·인프라)을 입력받아 불이 어디까지·얼마나 빨리 번질지 예측하고 위험도를 산출.

원문의 흐름 요약:

```
[입력] 운영 입력 격자 (기상·지형·연료·인프라)
  ↓
[B] 확산 예측 (ELMFIRE)
    출력: 도달시간 래스터 → 시간별 예상 피해면적(ha) / 확산속도(ha/h) / 화선 강도(kW/m)
  ↓
[C] 발화 후 위험도 판정
    ① 조건위험도 (0~100) — 발화 환경의 위험도 (AI Hub 위험도 기준 이식)
    ② ELMFIRE 확산 예측 보완 — 확산속도·도달 예상시각
```

##### 5.2.1.1 확산 예측 — ELMFIRE

**모델 선택 근거.** 두 대안 검토.
1. 딥러닝 기반 확산 예측: 발화부터 진압까지의 시계열 확산 경계가 필요하나 국내 공개 데이터에 없다(4.2 ①) → 지도학습 불가.
2. 물리 기반 오픈소스 FARSITE vs ELMFIRE 비교:

**[표 5-1] FARSITE와 ELMFIRE 비교**

| 항목 | FARSITE | ELMFIRE |
|:--:|---|---|
| 격자별 확산속도 | Rothermel 표면화 모델 | Rothermel 표면화 모델 (동일) |
| 2차원 확산 방향 | Anderson 타원형 형상 모델 | Anderson 타원형 형상 모델 (동일) |
| 화선 전파 방식 | Huygens (경계점 이동) | 레벨셋 방정식 (격자 함수 경계) |
| 공식 배포 | FlamMap[15] 통합 (Windows 전용) | 공식 GitHub + Docker[16] |
| 연료 파라미터 제어 | 소스 수정 필요 | fuel_models.csv 외부 파일로 제어 |
| IoU 보정 루프 | 구현 어려움 | CSV 교체 → 재실행으로 가능 |
| 래스터 파이프라인 통합 | 경계점 좌표 별도 관리 | 격자 단위, GeoTIFF와 통합 자연스러움 |

"본 과제는 Linux 서버 기반 자동화 파이프라인 환경이며 과거 산불 소실 경계를 이용한 IoU 기반 파라미터 보정이 필요하므로 **ELMFIRE를 채택**한다(Lautenberger[16], C. 2013, Fire Safety Journal 62, 258–268)."

**알고리즘 구성.** ELMFIRE는 세 단계로 확산을 계산.
1. **Rothermel 표면화 확산 모델** — 연료 하중·깊이·입경, 풍속, 경사로부터 격자별 최대 확산속도 R(m/min) 산출 (Rothermel 1972, USDA INT-115).[17]
2. **Anderson(1983)[18] 타원형 형상 모델** — 풍속 기반 장단축비로 2차원 확산 방향 결정 (USDA INT-305).
3. **레벨셋 방정식** — 격자 함수 φ=0 경계를 시간 전진하여 화선 위치 추적.

**구현 절차.**
1. **입력 격자 구축.** ELMFIRE는 확산 지역 전체의 지형·연료를 격자로 요구하지만 데이터셋은 지점 한 곳의 값만 제공 → 4장 운영 입력(임상도·DEM·기상·인프라)을 **30m 격자**로 정합해 입력 구성. 임상도는 표준 연료 코드(**Anderson-13**)로 변환. **ELMFIRE 엔진 자체는 수정하지 않는다.**
2. **파라미터 보정.** 연료 파라미터는 외부 파일(**fuel_models.csv**)로 분리되어 엔진 수정 없이 교체·재실행 가능. AI Hub 각 사건의 최종 소실 경계(fire_spread_track)를 정답으로 삼아 임상 유형별 계수를 보정: "파라미터 설정 → ELMFIRE 실행 → 최종 소실 경계 추출 → 실측 경계와 IoU 계산 → IoU 수렴까지 반복(**베이지안 최적화**)".
3. **출력.** 격자 단위 GeoTIFF 래스터(도달시각 toa, 화선 강도 flin, 화염 길이) → 시간별 소실 경계 폴리곤(지도 표출), 확산속도 V(ha/h), 화선 강도 I(kW/m, 진화 가능 여부 판단)를 파생.

##### 5.2.1.2 발화 후 위험도 판정

목적: 발화 직후 이 산불이 얼마나 위험한지를 정량으로 판단해 초기 의사결정(자원 투입·대피·진압)을 뒷받침. **① 발화 환경의 조건위험도**를 산출하고 그 한계를 **② ELMFIRE 확산 예측**으로 보완.

**① 조건위험도.** 저작도구 「위험도 기준」(4.2 ④·⑤)의 임계값과 가중치(**기상 0.35·지형 0.30·연료 0.25·인프라 0.10, 25변수**)를 계산 규칙으로 이식, 발화 지점 조건에 적용해 0~100 산출. 변수별 점수(1~5)와 가중치는 저작도구 기준표 그대로 사용, 가중평균 점수(1~5)를 0~100으로 선형 변환.

> 조건위험도 = 25 × ( (Σ 변수점수(1~5) × 가중치) / Σ가중치 − 1 )

**② 한계와 보완.**
- 발화 시점의 정적 조건만으로는 최종 규모를 예측할 수 없다. **101개 사건 분석에서 조건위험도와 최종 피해면적의 상관은 Spearman ρ=0.264(약함)**. **강릉 산불(2022.3, 4,190ha)**은 조건위험도 하위 20%였음에도 대형으로 확대.
- "대형화가 발화 시점 조건이 아니라 이후 불이 번지는 과정에서 비롯되기 때문이다." → 조건위험도가 담지 못하는 "번지는 속도"를 ELMFIRE 확산 예측(확산속도·도달 예상시각)으로 보완.
- 선례: 캐나다 **CFFDRS**는 기상 기반 잠재 위험 지수(**FWI**, 1970년 도입)[19]와 연료·지형 기반 확산 거동 예측(**FBP**, 1992년 정식 도입)[20]을 별개로 운영. 확산속도는 BC주 산불청이 대피령·인력 배치 결정에 실제 사용.[21]

**구현 절차.** 1. 조건위험도 산출·표출. 2. ELMFIRE 확산 예측 보완 — 확산속도·도달 예상시각 (5.2.1.1 연동).

#### 5.2.2 역할별 산불 임무 생성 모델

- 발화 후 예측 결과(5.2.1)를 입력받아 현장 역할별 임무를 법령·매뉴얼 근거와 함께 생성. "위험도·확산 판단은 물리 모델과 규칙이 수행하고, LLM은 확정된 근거 문서를 검색(RAG)하여 역할별 서술로 정리하는 역할만 맡는다."
- **근거 코퍼스 구축.** 생성 근거와 검증 근거를 서로 다른 출처에서 확보하기 위해 코퍼스는 데이터셋과 무관한 법령·지침 원문(4장 검증 근거용)으로 구성. 법령은 공개 자료, **기관별 실무매뉴얼은 정부 부처 안에서 열람되는 자료이므로 관계 기관에 공개를 요청해 확보**. 각 문서를 **조·항·호 단위로 분할**, 출처·기관·대응단계 메타데이터 태깅. 한국어 임베딩(**KURE-v1**) 벡터 색인과 **BM25** 색인을 나란히 걸어 하이브리드 검색 지원.

##### 5.2.2.1 역할 체계

역할은 **소방요원(FF)·구조요원(RW)·공무원(GO)** 3종. 각 역할 아래에 검색 필터로 쓰는 기관 목록을 둔다. 기관 목록은 「산불진화기관의 임무와 역할에 관한 규정」(**산림청예규 제733호**, 2026.8.25. 개정, 이하 「예규」)[32] 제17조·별표 1, 실무매뉴얼 "기관별 임무 및 역할" 표에서 임무가 명시된 기관으로 구성.

**[표 5-2] 역할과 검색 대상 기관**

| 역할 | 검색 대상 기관(메타데이터 필터) |
|:--:|---|
| 소방요원(FF) | 소방관서, 산림청 공중진화대(산림항공본부), 지상진화대(산불재난특수진화대·산불전문예방진화대), 군 지원부대, 산불예비진화대 |
| 구조요원(RW) | 119구조·구급대, 재난의료지원팀(DMAT)·보건소 |
| 공무원(GO) | 산림청(중앙산림재난상황실), 지방산림청·국유림관리소, 시·도, 시·군·구, 읍·면·동, 행정안전부, 경찰청, 국방부, 기후에너지환경부(국립공원공단), 국가유산청, 기상청 |

##### 5.2.2.2 역할 활성화 규칙

활성화는 **LLM이 아니라 규칙으로 판정**. 판정 변수: ① 대응 단계, ② 행정구역 경계 통과 여부.

- **대응 단계**: 산림재난방지법 시행령 별표 3[6] 기준을 5.2.1 예측값에 적용. 피해면적 **10ha 미만 초기대응, 10ha 이상 100ha 미만 확산대응 1단계, 100ha 이상 확산대응 2단계**. **평균풍속(3·11m/s)**이나 **주요시설 피해 우려(20동)**가 상위 단계면 상향. 공식 발령 주체는 산림청장(법 제32조)이므로 예측값으로 산출한 단계는 **"예측상 대응 권고 단계"**로 표기해 공식 발령 단계와 구분.
- **행정구역 경계**: 확산 폴리곤과 행정경계 GIS[22]를 중첩해 계산. 2개 이상 시·군·구는 시·도지사가, 2개 이상 시·도는 산림청장이 통합지휘한다는 **법 제34조**에 따라, 경계 통과가 예상되면 공무원 역할에 상위 지휘기관을 추가하고 **"지휘권 인계 준비"**를 권고로 표기.

**[표 5-3] 대응 단계별 활성화 기관 (예규 별표 1 기준)**

| 대응 단계 | 소방요원(FF) | 구조요원(RW) | 공무원(GO) |
|:--:|---|---|---|
| 초기대응(<10ha) | 소방관서(소방차 출동, 도시지역 초동진화), 지상진화대, 산림항공본부 헬기, 군 헬기 (요청 시) | 119구조·구급대(인명위험 신고·출동 요청 시) | 산림청 상황실, 시·군·구 산림부서, 읍·면·동, 경찰(교통통제), 기상청, 국립공원공단·국가유산청(관할 대상 시) |
| 확산대응 1단계(10ha 이상 100ha 미만) | 위 + 인접 지자체·소방 진화자원 추가 동원 | 위 + 주민대피 지원(예규 제14조) | 위 + 시장·군수·구청장 또는 국유림관리소장(통합지휘본부장), 주민대피 조치, 경찰(주민대피 지원) |
| 확산대응 2단계(100ha 이상) | 위 + 군 헬기 추가 지원, 공중지휘기 운영 | 위 + DMAT·보건소(다수 사상자 우려 시) | 위 + 시·도지사 또는 산림청장(대형 산불 통합지휘), 산불상황분석자문단, 행정안전부 |

"별표 1은 요청·필요·관할 조건이 붙은 항목이 많으므로, 표의 괄호 조건은 규칙의 입력 변수로 두고 조건 미충족 시 해당 기관을 비활성화한다."

##### 5.2.2.3 처리 파이프라인 (RAG)

[그림 5-3: RAG 처리 파이프라인] — 제목 "역할별 대응 요령 생성 파이프라인 (RAG)", 우상단 주석 "5.2.2.3 · 예측 결과 1건 → 보고서 1회 생성". 여섯 박스로 구성되며 03~05가 "RAG" 영역으로 묶여 있다.

| 단계 | 내용(그림 표기) |
|---|---|
| 01 예측 결과 | 5.2.1 산출물: 확산·위험도·도달시간 + 상황 피처 |
| (상단 분기) 현장 분석 생성 | LLM 서술 · RAG 없음 · 값 재계산 없음 → 바로 06으로 |
| 02 규칙 판정 | 대응단계·경계 통과 → 역할별 활성 기관 (LLM 미사용) |
| 03 질의 생성 | 역할·상황·정보 질문. FF 3 · RW 3 · GO 4 |
| 04 임베딩 검색 (RAG) | KURE-v1 + BM25, 기관·단계 필터, 상위 5개 청크 |
| 05 생성 LLM (RAG) | EXAONE 4.0 32B, 청크 번호 인용 [1]~[5] |
| 06 보고서 조립 | 현장 분석 + 역할별 임무 부여 + 근거 각주 |

**[표 5-4] RAG 구성요소와 근거**

| 구성요소 | 선택 | 근거 |
|:--:|---|---|
| 임베딩·검색 | KURE-v1 벡터 + BM25 하이브리드로 상위 5개를 가져온다. 검색 전 활성 기관·대응단계 메타데이터로 후보 제한 | 한국어 검색 벤치마크 MTEB-ko-retrieval에서 KURE-v1 평균 nDCG@10 0.7616로 상위. 공개 모델(MIT)[23] |
| 투입 청크 수 k=5 | 상위 5개를 프롬프트에 투입. 5개 미만이면 있는 만큼 넣고 "근거 부족" 표기 | 인용 생성 벤치마크 ALCE 기본 설정(5개 문단)[24], 재난 QA 벤치마크 DisastQA[25]도 정답 1 + 방해 4로 Top-5 상황 모사 |
| 생성기 | EXAONE 4.0 32B, Reasoning mode[26] | 추론·비추론 모드 통합 공개 모델 (선정 사유 5.6.1) |
| 인용 형식 | 청크를 [1]~[5]로 넣고 각 문장 끝에 근거 청크 번호를 명시, 각주로 문서명·조항 표기 | ALCE 인용 프롬프트 형식(문단 번호 대괄호 인용)과 동일. 인용 타당성은 5.4 근거 충실도로 평가 |

> (정리자 주) 표 5-4의 "선정 사유 5.6.1"은 원문 그대로이며, 현재 목차에는 5.6이 없다. 내용상 5.5 개발환경 말미의 "언어모델 선정 사유"를 가리키는 것으로 보인다(수정 전 문서의 절 번호가 남은 것으로 추정).

##### 5.2.2.4 보고서 생성 절차와 출력

- 보고서는 예측 산출 시점 기준 **1회** 생성.
- ① **현장 분석**: 5.2.1의 수치·지표(피해면적, 확산 속도·방향, 도달 예상시간, 주요시설 피해 우려, 예측상 대응 권고 단계, 경계 통과 여부)를 **검색 없이** 서술문으로 정리(**LLM은 값을 재계산하지 않음**).
- ② **임무 부여**: 역할별 정보 항목마다 질의 1개를 만들어 RAG 실행, 답변을 모음. 프롬프트는 ① 역할, ② 현재 상황, ③ 정보 질문으로 구성.
- 문체는 **격식체 하십시오체**로 통일.

**[표 5-5] 보고서 구성**

| 구분 | 역할 | 항목 | 산출 방식 |
|:--:|:--:|---|---|
| 현장 분석 | (공통) | 위치·시각, 예측상 대응 권고 단계, 확산 방향·속도·범위, 도달 예상시간, 주요시설 피해 우려, 경계 통과 여부 | 5.2.1 결과 → LLM 서술(RAG 없음) |
| 대응 임무 부여 | 소방요원 | 진화 우선지역, 진입 시 위험요인, 주요 보호대상 | 질의 3개, RAG |
| 대응 임무 부여 | 구조요원 | 구조 우선순위, 이동·이송 계획, 위험구간 | 질의 3개, RAG |
| 대응 임무 부여 | 공무원 | 대피 우선순위, 자원배분, 추가 자원 필요성, 행정 대응 | 질의 4개, RAG |

"근거는 각주로 인용 번호별 문서명·조항을 표기하며, 이는 검색 결과 메타데이터로 산출한다."

### 5.3 표출

사용자가 보는 화면은 두 계층.

- **상황 표출(5.2.1 출력)** — 확산 예측 지도(도달시각 등고선, 시간별 소실 경계)와 위험도를 함께 제시. 위험도는 조건위험도(0~100)와 요인(**W·T·F·I**) 분해를 보여주고, 그 옆에 ELMFIRE 확산속도·주요시설 도달 예상시각을 병기하여 조건만으로 드러나지 않는 위험을 보완.
- **임무(5.2.2 출력)** — 역할(FF/RW/GO) 탭별로 현장 분석과 임무 목록을 제시하며, 각 임무 문장에는 근거 문서·조항 각주를 함께 표시.

> (정리자 주) W·T·F·I는 원문에 풀어 쓰여 있지 않으나 5.2.1.2의 가중치 축(기상·지형·연료·인프라) 순서와 일치한다.

### 5.4 평가 지표

"평가는 자동 지표로만 채점하며, 결과는 대리 지표로 보고하고 현장 유효성을 입증한 것으로 쓰지 않는다. 모든 검증은 학습·보정에 쓰지 않은 사건으로 분리(**hold-out**)하여 수행한다."

**[표 5-6] 평가 지표**

| 대상 | 지표 | 채점 방식 | 근거 |
|:--:|---|---|---|
| 확산 예측(5.2.1) | IoU (확산 경계 일치도) | ELMFIRE 예측 경계와 실측 경계(AI Hub fire_spread_track)의 교집합÷합집합. 시계열 경계가 없어 **최종 확산 범위** 기준 | 예측·실측 소실 영역의 겹침 정도를 재는 표준 지표. 산불 확산 모델 검증에 널리 쓰임(FARSITE 검증, Fire Ecology 2022)[27] |
| 임무 생성(5.2.2) | 검색: Recall@5, nDCG@5 | 질의별 관련 청크 기준 집합을 LLM으로 판정(활성 기관 필터 통과 청크 전체를 후보로 두어 누락도 반영) | 재난 검색 벤치마크 DisastIR[28]이 관련성 레이블을 LLM으로 생성·일부 사람 대조한 방식 |
| 임무 생성(5.2.2) | 생성: 근거 충실도, 답변 관련성 | RAGAS 정의 사용(버전·채점 LLM·임베딩 모델 고정 기록) | RAGAS: 충실도="답변 주장 중 문맥에서 추론되는 비율", 답변 관련성="답변 역생성 질문과 원질의 유사도". 사람 판단 일치율 0.95·0.78[29] |

**[표 5-7] 목표치와 근거 (잠정 내부 목표)**

| 지표 | 목표 | 근거 |
|:--:|:--:|---|
| IoU | ≥ 0.5 | 잘 보정된 산불 확산 모델의 정확도는 대체로 IoU 0.5~0.67 수준. FARSITE 검증[27]에서 겹침 지표(Sørensen)가 잘 만든 입력 0.70~0.80, IoU로 환산 시 약 0.54~0.67(IoU=SC/(2−SC)). 첫 보정 단계·최종 경계만 검증 가능한 한계를 반영해 0.5를 잠정 목표로 둠 |
| 검색 Recall@5 | ≥ 0.80 | KURE-v1 한국어 범용 검색 Recall@10 0.8629[23]. 재난 도메인 하락과 k=5를 반영해 0.80을 잠정 목표로 둠 |
| 근거 충실도 | ≥ 0.90 | RAGAS 원 논문[29]의 사람 판단 일치율(충실도 0.95)과 32B 공개 모델의 한계를 감안하여 0.90을 잠정 하한으로 둠. 선행연구의 개별 수치는 데이터·조건이 달라 직접 인용하지 않음 |
| 답변 관련성 | ≥ 0.80 | RAGAS 원 논문[29]의 사람 판단 일치율(답변 관련성 0.78)이 충실도보다 낮은 점을 감안하여 0.80을 잠정 목표로 둠 |

※ **Ablation 실험 제안.** RAG 유무 두 조건을 같은 질의·사건으로 비교하여 RAG의 기여를 정량화. "위 목표치는 선행연구를 참고한 내부 잠정 목표이며, 서로 다른 데이터·조건의 점수를 직접 환산한 것이 아니다."

1. 산림청 실무매뉴얼 등은 정부 부처 안에서는 열람 가능하지만 외부 팀에는 **대외비**에 해당하여 공개를 요청해 받아야 하는 문서. 정부가 이런 문서를 다루는 시스템을 도입할 때는 국외 모델보다 **국내 기업이 개발·공개한 모델**이 이후 모델 갱신·수정 대응에 유리 → 국내 공개 모델로 한정.
2. 32B는 A6000 48GB 한 장에 4비트 양자화로 적재하여 KURE-v1 임베딩과 색인을 같은 서버에 함께 상주시킬 수 있는 규모. 실행 조건(양자화 형식, 문맥 길이, 동시 요청 수)은 구현 단계에서 측정해 고정 기록.
3. 추론·비추론 모드를 하나의 모델로 제공해 **현장 분석(비추론)과 임무 생성(추론)을 모델 교체 없이 처리**.

## 7. 기대효과

기대효과는 1장의 두 공백(확산 예측이 대응 행동으로 자동 연결되지 않는 문제, 그 연결이 소수 인력 수작업에 묶여 있는 문제)이 해소될 때 현장에 생기는 변화로 서술. 사회적·산업적 효과는 산불 대응 체계와 수요 주체 관점, 기술적 효과는 5장 설계 방법론 관점, 팀 성장 목표는 7.3.

### 7.1 사회적·산업적 효과

"사회적으로는 소방·산림 대응 업무의 AI 전환(AX)을 예측 단계에서 대응 판단 단계까지 확장한다는 점이 가장 직접적인 기여다."

- **예측과 대응의 연결 자동화**: 발화점 또는 화선 위치만 입력하면 확산 예측→역할별 임무 생성→한 화면 표출까지 사람 개입 없이 처리. 소수 전문 인력이 회차마다 손으로 만드는 연결 작업[3]을 시스템이 대신 → 확산이 빠를수록 늘어나는 회차별 판단과 장시간 산불의 누적 부담을 인력 증원 없이 줄임.
- **소방대응 AX의 실증 사례**: 정부 「AI 기반 산불·연무 확산 감시·예측」 사업[8]은 예측과 경로 산출까지만 다룸. 본 과제는 그 다음 단계를 물리 모델·규칙 판정·근거 기반 생성으로 자동화 → "시간이 생명과 직결되는 소방 대응 업무에서도 통제된 형태의 AI 자동화가 가능함을 보인다."
- **역할별 분화와 지휘 공백 축소**: 현행 상황 전파는 모든 기관에 같은 내용을 보내지만, 본 시스템은 동일 예측을 3역할 임무로 나누고 대응 단계·행정구역 경계 규칙으로 활성화 기관을 정함. 지휘권 인계가 예상되면 미리 권고로 표기 → 통합지휘 전환 공백 축소.
- **판단 근거의 정량화와 추적**: 확산속도와 주요시설 도달 예상시각은 공무원의 대피 우선순위·주민대피 조치와 소방요원의 진입 위험 판단에 정량 근거 제공. 임무 문장마다 조항 각주, 근거 5개 미만이면 「근거 부족」 → "사람의 판단을 대체하지 않고 근거를 제시하는 역할에 인공지능을 머물게 한다."

| B2G | 지방자치단체·산림청·소방관서 대상. 물리 모델·규칙 엔진·국내 공개 언어모델 조합이라 상용 API 없이 GPU 서버 한 대로 운용하고, 입력이 공공 개방자료와 정부 내부 열람 자료(법령·매뉴얼)로 구성되어 데이터 구입 비용이 없다. 지휘권자가 바뀌어도 같은 근거로 상황을 재해석하는 표준 도구가 된다.[31] |

### 7.2 기술적 효과

- 물리 기반 확산 시뮬레이션(ELMFIRE[16]), 위험도·역할 활성화 판정, 검색 증강 생성(KURE-v1[23] + BM25 + EXAONE[26])이라는 성격이 다른 기술들을 하나의 파이프라인으로 결합한 사례.
- 시계열 확산 라벨이 없는 문제를 물리 모델과 연료 파라미터 보정(최종 소실 경계 IoU)으로 푸는 접근 → 정답 데이터 확보가 어려운 재난·안전 도메인에 일반적으로 적용 가능한 방법론.
- **언어모델 위험을 구조로 통제**: 확산 경계·위험도·대응 단계는 언어모델을 경유하지 않게 경로 분리. 생성 근거(법령·매뉴얼)와 보정·검증 근거(AI Hub 실측 경계)를 서로 다른 출처로 둠. 언어모델은 확정된 값을 서술하고 검색된 조항을 인용하는 역할로 한정.
- 검색(Recall@5·nDCG@5)·생성(RAGAS[29] 충실도·답변 관련성)·확산(IoU)을 hold-out 사건으로 자동 채점하고 RAG 유무를 절제 실험으로 대조하는 평가 체계 → "평가를 위한 사람 투입이 제한적인 도메인에서 언어모델 적용의 신뢰성을 검증하는 구체적 사례".

**[표 7-2] 공통 성장 목표**

### 모델·알고리즘·지표

| 용어 | 정의(원문 기준) |
|---|---|
| ELMFIRE | 채택한 물리 기반 오픈소스 확산 모델(Lautenberger 2013). Rothermel + Anderson 타원 + 레벨셋. 공식 GitHub + Docker, fuel_models.csv 외부 제어. 버전 ELMFIRE1.1. 엔진은 수정하지 않음 |
| FARSITE | 비교 대안. Huygens 경계점 이동 방식, FlamMap 통합(Windows 전용) |

| Anderson(1983) 타원형 형상 모델 | 풍속 기반 장단축비로 2차원 확산 방향 결정(USDA INT-305) |

| 레벨셋 방정식 | 격자 함수 φ=0 경계를 시간 전진하여 화선 위치 추적 |
| fuel_models.csv | ELMFIRE 연료 파라미터 외부 파일. 교체·재실행으로 보정 루프 수행 |
| toa / flin | ELMFIRE 출력 래스터: 도달시각(toa), 화선 강도(flin). 화염 길이도 출력 |
| 베이지안 최적화 | 파라미터 보정 루프에서 IoU 수렴까지 반복하는 최적화 방법 |
| IoU | 예측 경계와 실측 경계의 교집합÷합집합. 최종 확산 범위 기준. 목표 ≥ 0.5 |

| ALCE | 인용 생성 벤치마크(Gao et al., EMNLP 2023). k=5와 대괄호 번호 인용 형식의 근거 |
