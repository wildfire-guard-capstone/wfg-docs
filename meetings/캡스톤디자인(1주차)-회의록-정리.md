## 논의 내용

### 1. 제안서/PPT 수정 방향

**부족한 부분 공통 인식:**
- 평가 기준 및 정량적 지표 부재
- 핵심 기능 4가지(위험도, 확산, 대응 보고서, RAG 검증)에 대한 데이터 근거 부족
- 현재 산불 대응 시스템 현황 조사 미흡
- **AI를 과다 사용해 제안서 근거가 약함 → 이번 조사는 직접 진행**

**기능별 문제점:**
- **위험도:** 어떤 데이터를 왜 써야 하는지 근거 없음. 기준 자체를 팀이 직접 정의해야 함
- **확산:** 공개된 확산 예측 데이터 없음 → 물리 모델을 직접 구현해야 하는 상황. 실현 가능성 검토 필요
- **대응 보고서:** 보고서에 들어갈 요소(8개 필드)가 무엇인지 어디에도 정의되지 않음. 실제 산불 대응 보고서 조사 필요
- **RAG:** 임베딩 + BM25는 고전 기술 → 제안서에서 RAG라고 소개한 방식이 할루시네이션 의심. 정확한 RAG 개념 재정립 필요
- **골든타임:** 개념 모호, 대피 소요 시간 산출 방법 불명확 → 관련 자료 조사 후 존치 여부 결정

### 2. 아키텍처 이해 공유

- **확산 예측:** AI허브 데이터에 시계열 없음(사후 확정 경계만 존재) → 물리 모델(로터멜, 앤드레슨, 휴엔 화선) 사용하여 IoU 스코어로 평가
- **RAG 재정의:** 법령·매뉴얼을 조항 단위로 색인 후 검색 기반 근거 검증. 표준 RAG가 아닌 변형 형태임을 명시
- **사전 구축 데이터:** 지형/연료(30m 격자), 법령 색인, 확산 파라미터
- **LLM:** CoT 데이터로 파인튜닝, 프롬프트 엔지니어링 병행
- **대응 보고서 역할:** 우선 시민 + 진압대원 2개에 집중, 이후 4개(공무원, 구조 요원)로 확장

### 3. 기타 논의

- 교수님 제안: 산림청/소방서 인터뷰 → 프로토타입 완성 후(10월 중순) 진행 검토
- 산불 사후 보고서(소방 처리 이후 작성 문서) 존재 여부 확인 및 활용 검토
- Confluence 접근 권한 문제 → 관리자 권한 부여로 해결
- 중국산 LLM(Qwen) 대안 모델 검토 필요 (교수님 피드백)
