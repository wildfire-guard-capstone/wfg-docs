**④ 위험도 정의 결론 (김지오·임성민)**
- 전제: 위험도는 **산불이 난 뒤**의 것이고, **예측 모델로 예측한 산불**을 기준으로 함 [L582-589]
- AI 허브 구조: 기상·지형·연료·인프라 4개 항목을 가중치로 점수화함. 사후 데이터인 인프라는 **예측 범위 안 마을이 받는 영향 정도를 가중치로** 반영하는 것으로 대체 [L590-594]
- 기준 시점: 시간대마다 위험도가 달라지는데, 황승준는 **고정된 단일 값**이어야 한다고 봄 → **P5(주민 대피 관련)를 1순위**로 하고 2순위로 P8을 언급함. 황승준는 하나로 간다면 P5가 좋다고 함 [L601-628]
- 척도: 0은 "불이 없다"는 뜻이라 애매하고, 0~100은 산림청 **산불위험지수와 혼동**할 수 있음 → **1~5점 그대로** [L628-635]. 보고서에는 산불위험지수(발생 전)를 소개하고, 우리는 AI 허브를 바탕으로 가중치를 다시 정의했다는 흐름으로 쓰자(황승준) [L637-647]
- 한계: AI 허브의 1~5점은 ToT 과정에서 판단을 가지치기하려고 쓰는 **중간 점수**이지 산불의 실제 위험 판정용 지표가 아님. 국가 대응 단계와 연결하려 해도 연결되지 않아, 연결하려면 새로 만들어야 하고 그러려면 근거가 필요함. 실제 산불 데이터는 101건뿐이고 수치가 난수에 가까우며 2~3단계에 몰려 불균형함 [L653-667]
- 폴리곤–격자: 30m×30m 격자별 포함 비율로 **면적 가중합**을 함. 풍속·풍향 같은 벡터량은 가중합하지 않고 면적에 따라 바뀌는 수치만 가중합함 [L668-681]
- 동시다발 산불: 4개 안 중 **산불별로 각각 위험도를 산정**하는 안을 택함(자원 배분 판단에 유리). 퍼지다가 **붙기 시작하면 하나의 산불로 보고 재예측**함. P5 기준으로 합쳐지면 하나로 봄. 황승준는 처음엔 "가까우면 하나로"를 제안했지만 가까움의 기준이 애매해 이 방식에 동의함 [L681-726]
- 취약계층: 면 단위 인구수는 확보했고, 지역별 취약계층 비율로 **합성 데이터**를 만들어도 됨 [L735-752]
- 근거 표시: PPT의 "위험 점수 → 근거 검색 → LLM 판단 → 안전 규칙"에서 위험 점수는 별개임. 위험도의 근거는 **계산 방식(공식)**이므로 그것을 화면에 보여 주면 되고, 근거 검색은 RAG 쪽 이야기임 [L759-812]
- 결론: **합의**

- IoU: 황승준는 물리 모델로는 0.5 이상이 어렵다고 봄 [L1028-1036]. 김지오: 교수님의 "0.5는 낮다"는 바운딩 박스 탐지 관점이고, 확산 예측은 예측이 크든 작든 IoU가 크게 떨어진다. 높이려면 AI를 쓰거나, 0.5를 설명해야 한다 [L1043-1060]. 황승준: 현재 물리 모델이 0.5 정도라는 공식 논문 근거로 반박하면 된다 [L1049-1056]
- 결론: **보류** — 내일 데이터를 받을 수 있는지 확인한 뒤 물리 모델/AI를 결정 [L1008, L1063]

**⑥ 위험도 활용 방식**
- 1~5점 위험도를 어디에 쓸지에 대해 황승준·홍준서는 **"나타내라고 했으니 나타낸다"**(PPT에도 위험도·우선순위를 나타내라고 되어 있음)는 입장이었고, 김지오이 수긍함 [L1066-1088]
- 국가 단계와 연결하는 것은 앞서 본 대로 불가함 [L1094-1095]
- 결론: **합의** — 위험도는 별도로 표시만 함

**⑦ 성능 지표 ① 확산 예측**
- 황승준: **IoU는 반드시** 넣고, **재현율**(불이 난 마을을 놓치지 않음)을 추가하자. 재현율은 높게 나올 수 있어서 0.9로 잡아도 될 것. 물리 모델이면 IoU는 0.66 정도가 최대로 봄 [L1103-1125]
- 홍준서: 조사해 보니 산불 확산 예측 IoU는 논문상 0.26 정도가 최대였고, 이미 탄 지역을 맞히는 것과 미래를 예측하는 것은 달라서 0.5도 충분히 높으며 0.8은 너무 높다 [L1230-1232]. IoU와 재현율을 동시에 높이기는 어렵다 [L1256-1266]
- 김지오 정리: FN(미탐)이 적을수록 **재현율↑ → 인명 피해 방지**, FP(과대 예측)가 적을수록 **정밀도↑ → 불필요한 대피·진화 자원 분산 억제** [L1320-1367]
- 쟁점: F2를 넣을지. 황승준는 좋은 결과가 나오는 것만 쓰고 싶어 F2를 빼고 4개를 쓰자고 함 → 김지오은 F2가 재현율에 가중치를 더 준 것(인명 우선)임을 확인했고, 모두 혼동행렬 하나에서 나오는 값이라 빼기가 애매하다고 봄 [L1389-1443]
- 결론: **합의** — 과학원 설명서의 지표를 따라 **IoU·재현율·정밀도·F1·F2 5개** [L1449-1452, L1757-1760]

**⑧ 성능 지표 ② 대응 제안(RAG)**
- 황승준: 검색은 Recall@5를 유지하고 생성은 인용 재현율, 이렇게 2개 정도를 생각함. 휴먼 평가는 아직 찾아보지 못함 [L1140-1146]
- Recall@5의 의미: 상위 K=5개 청크를 가져오기로 해서 붙은 이름인데, 왜 5개냐고 물으면 "AI가 5개로 하라고 했다"는 것 외에 답이 없음(김지오) [L1472-1485]. 홍준서: 5개가 정확도가 가장 높고 너무 많으면 성능이 떨어진다는 자료가 있음 [L1230, L1488-1494]. **원래는 K=3~7 정도를 실험해 가장 점수가 높은 K를 고르는 것**이 정석이고, 교수님께도 "실험하면서 정하겠다"고 답했었음 [L1497, L1850-1858, L1883-1885]
- 휴먼 평가: RAG는 사람이 만든 정답지와 비교해야 하는데, 지난번에는 정답지까지 AI가 만들게 해서 의미가 없었다(교수님이 지적한 이유) [L1149-1188]. → 시간이 부족하니 **정답지 작성은 AI로 하고 우리가 한 것으로 하자**는 안을 "가장 현실적인 방안"으로 받아들임 [L1192-1215]. 뒷받침 여부 판단은 원래 사람이 하지만 최신 모델이면 가능할 수도 있다고 봄 [L1847-1849]
- 평가 대상 범위: 대분류(확산 예측·위험도 산정·규칙 판정·근거 생성·AI 질의응답·시스템 성능) 중 **규칙 판정은 공식에 넣으면 나오는 것이라 성능 평가가 필요 없고**, 질의응답·상황 변경도 뺌 [L1465-1467, L1682-1748]
- RAGAS 4개 지표의 이름을 바꿔 쓰기로 함(홍준서·김지오) [L1713-1741]
  - 생성: **근거 충실도**(Faithfulness, 가져온 근거를 답변에 얼마나 썼나), **답변 관련성**(Answer Relevancy, 질문과 답변의 임베딩 유사도) [L1760-1801]
  - 검색: **컨텍스트 재현율**(필요한 정보를 다 가져왔나), **컨텍스트 정밀도**(관련 문서가 상위에 있나) [L1773, L1804-1830]
- 결론: **합의** — 대응 제안 에이전트는 생성 2개 + 검색 2개 [L1748-1773]

**⑨ 산림청 문의처 정리**
- 경과(김지오): 국립산림과학원 박사님은 "데이터 제공은 중앙상황실 쪽"이라고 했고, 그쪽은 제대로 답하지 못하고 산불방지과로 넘겼으며, 산불방지과 담당자는 출장 중이었음 [L1561-1575]
- 후보: 중앙산림재난상황실, 산불방지과, 산림재난 예측·분석 시스템 운영 주무관, 과학원 연구사(박사님) [L1570-1585, L2049-2065]. 사무관에게 바로 연락하는 것은 피하고 주무관 선에서 연락하자 [L1608-1630]
- 황승준: "산불 예측 서비스를 만들고 있는데 이런 데이터가 필요하다"는 식으로 요청함. 받을 수 있는 것은 **폴리곤과 상황 지도 2개** 정도로 봄 [L1661, L2069-2076]
- 과학원(연구원)이 서울 회기(경희대 근처)에 있어서, 자료를 못 받으면 **직접 찾아가는 것**도 방법으로 나옴 [L1995-2008]
- 결론: **합의** — 황승준가 전화·메일로 문의함

**⑩ 하한선 근거**
- 확산 예측: 하한선은 벤치마킹을 위한 것이므로 과학원 설명서 표의 **과정 기반(물리) 모델 수치(0.58 등)를 하한선**으로 쓰고, 설명서 표에 우리 캡스톤 모델 행을 넣어 비교하는 방식이 가장 깔끔함. 황승준는 물리 모델 값을 하한선, AI 모델 값을 상한선으로 하자고 제안함 [L1923-1954]
- 다만 설명서에는 참고문헌이 없음(뒤쪽 목록은 발간 자료 제목 목록일 뿐) → 그 수치의 **원 출처 논문을 따로 찾아야** 함 [L1957-1983, L2029-2040, L2086-2089]
- RAG 지표: 기존에 어떤 하한선을 썼는지 찾아봐야 함. 교수님 질문의 취지는 "검색만 하면 되는데 왜 95%가 아니라 80%냐"였음 [L1895-1908]. 이전 PPT 수치의 근거는 **RAGAS 원 논문과 KURE v1(고려대, 한국어 범용 검색)**이었음을 확인했고 그대로 써도 된다고 봄 [L2146-2156]
- 지난 분석서에 참고문헌을 넣지 않았으니 **이번에는 넣어야** 함 [L2107-2108]
- 결론: **합의**(확산 지표 하한선 방식) / RAG 지표 하한선 수치는 **보류**

**⑪ 수정 계획서 방향 · 다음 회의 일정**
- 수정 계획서는 교수님 피드백과 우리 자체 피드백을 반영하고 성능 평가를 반영함. **확산 예측 모델은 물리 모델로 쓰고**(데이터를 못 받을 수 있으므로), 바뀌면 프로토타입을 낼 때 수정 사항을 적음 [L2179-2196]
- 임성민이 불참해 오늘 내용을 따로 공유해야 함 [L2208]
- 다음 회의: 목요일은 김지오이 안 되고(18시 이후만 가능), 금요일(10/9)은 공휴일이라 이른 시간이나 비대면으로 하자는 안이 나옴 → **토요일 12시쯤**을 중심으로 황승준가 투표를 올림 [L2212-2250]
- 결론: **합의**(일정은 투표로 확정)

**⑫ 프로토타입 범위 · 지도 · 서버 구조**
- 서버 연결 여부: 시간상 **거의 못 함 → 목업 수준**이고, 기존 목업을 최대한 활용해 보강함 [L2259-2283]. 프로토타입은 피그마식 디자인을 기획서처럼 흐름대로 보여 주는 것이라 실제로 동작할 필요가 없음(황승준) [L2459-2474]
- 지도: 실제로 쓸 수 있는 현실적인 지도가 필요함. PostGIS는 DB이고, 후보는 OpenMapTiles와 네이버 지도 API [L2287-2307]. 네이버 지도에서 대피소 검색이 되는지 확인해 봄(민방위·지진 대피소 위주로 나옴) [L2310-2346]
- 화면: 통합 지휘권자·상황 보고자·전산 관리자(열람자) 화면 [L2350-2367]. 대응 제안 예시는 LLM이 만든 텍스트를 스크린샷으로 보여 줌 [L2371-2381]
- 구성: 1~4장은 그대로 두고 **유스케이스 흐름대로** 보여 줌. 예를 들어 "대피 완료"를 누르면 제안이 1판에서 2판으로 바뀌는 과정을 캡처함 [L2493-2499, L2512-2515, L2595-2620]. **"AI로 생성된 화면입니다" 문구**를 넣어야 함(지난번에는 넣지 않았음) [L2483-2490]
- 요구사항 추적 매트릭스(유스케이스–기능–비기능–클래스·시퀀스 연결): 교수님이 좋아했지만 **시간이 남으면 마지막에** 넣기로 함 [L2542-2586]
- 분석서 정리가 필요한 부분: 확산 예측 화면에 위험도가 들어간 위치, 동시다발 시 산불별 위험도, 이벤트 로그 위치 [L2622-2629]
- 서버: 웹(대시보드) 서버 1대에 포트 2개를 열고 GPU 서버(학교)와 통신하는 구조. GPU 서버는 현재 김지오만 접속할 수 있고 추가 요청도 가능함 [L519-526, L2411-2449]
- 프로토타입 PPT는 이번 주에 완성하지 않아도 되며, 다음 주에 요구사항 분석서 때처럼 나눠 쓰고 한 명이 통합함 [L2635-2639]
- 결론: **합의**

**⑬ 작업 분담**
- 할 일 3가지: ①수정 계획서 ②프로토타입 ③데이터·서버 [L2899-2907]
- ELMFIRE를 1주 안에 완성하는 것은 불가능한 규모라서, 계획을 잘 세우고 데이터를 많이 넣어 줘야 구현할 수 있음(황승준) [L2938-2952]. 프론트–백 JSON 명세를 먼저 만들자는 안은 필요 없다고 정리함 [L2962-2986]
- 프로토타입 방식: 처음에는 "각자 배치도를 만들어 와서 결정"하는 안이 나왔지만 일이 많아진다고 봄 → **한 명이 기존 목업 기준으로 수정·추가·삭제 목록과 배치도를 최대한 많이 가져오고, 회의에서 하나씩 반영 여부를 정하자** [L2745-2815, L3214-3224]
- 확정 분담 [L3020-3063, L3168]
  - **수정 계획서: 김지오·홍준서**
  - **프로토타입: 임성민** — 관리자·사후 보고자는 빼고 **통합 지휘권자 UI만**, 불필요한 요소를 제거한 버전 2
  - **데이터·서버: 황승준** — 산림청 문의, 데이터 정리, 서버 개설
- 서버 작업 범위: 프로토타입은 **서버에 연결하지 않는다**. 황승준는 서버를 열고 Docker 컨테이너 등 ELMFIRE 구동 환경과 배포 기초 작업을 하고, **서버 간 통신 준비**까지 함 [L3066-3156]
- PPT 분담은 토요일에 결정 [L2878, L3230]
- 결론: **합의**

**⑭ 지도 데이터(도로·철도) 확보 방법**
- 황승준는 지도에 레이어가 너무 많으니 빼고 싶어 함. 김지오은 통합 지휘권자가 AI 말만 믿지 않고 지도를 보며 판단하므로 **도로·철도·대피로는 필요하다**고 봄 [L3241-3314]
- OpenMapTiles는 오픈소스이지만 한국 시설 정보가 없음. 네이버 지도 API는 **유료**라서(Static Map 1건당 요금 발생) 그냥은 쓰기 어려움. 공모전 예선을 통과하면 쓸 수 있음 [L3271, L3343-3375]
- 황승준: 도로·철도 데이터(좌표)를 가져와 표시·숨김이 되는지 확인해 보겠음 [L3318-3319, L3369]
- 결론: **보류**

## 4. 결정사항
- **확산 예측 성능 지표: IoU·재현율·정밀도·F1·F2 (5개)** — 국립산림과학원 알고리즘 설명서의 평가 방식(혼동행렬 기반)을 따름. 재현율=인명 피해 방지, 정밀도=자원 분산 억제 [L1320-1367, L1449, L1757-1760]
- **확산 예측 하한선: 설명서의 과정 기반(물리) 모델 벤치마크 수치를 사용**하고 원 출처 논문을 찾음 [L1937-1954, L2086-2089]
- **대응 제안 성능 지표: RAGAS 4개(근거 충실도·답변 관련성 / 컨텍스트 재현율·컨텍스트 정밀도)** — 이름을 바꿔 사용 [L1713-1773]
- **규칙 판정·AI 질의응답·상황 변경은 성능 평가 대상에서 제외** — 규칙 판정은 공식에 넣으면 나오는 값이기 때문 [L1685-1748]
- **휴먼 평가용 정답지는 AI로 작성** — 시간 부족을 이유로 "가장 현실적인 방안"으로 받아들임 [L1192-1215]
- **위험도: AI 허브 기반 1~5점 유지, P5 기준 단일 값, 격자 면적 가중합, 동시다발은 산불별 산정(붙으면 하나로 재예측)** — 0~100은 산불위험지수와 혼동되고, 산불별 산정이 자원 배분 판단에 유리함 [L628-635, L668-723]
- **위험도 근거 = 계산 방식(공식) 표시**, 위험도는 별도로 나타내기만 함 [L793-809, L1066-1088]
- **수정 계획서에는 확산 예측을 물리 모델로 기재** — 산림청 데이터를 못 받을 수 있음 [L2186-2189]
- **예측 모델은 물리 모델과 AI(과학원 알고리즘)를 병행**하고 산림청 회신 뒤 결정 [L542-543, L1008]
- **프로토타입은 서버 연결 없이 기존 목업 보강, 유스케이스 흐름으로 구성, "AI로 생성된 화면" 표기** [L2259-2283, L2483-2515]
- **분담: 수정 계획서 김지오·홍준서 / 프로토타입 임성민 / 데이터·서버 황승준** [L3020-3063, L3168]
- **이번 분석서·계획서에는 참고문헌을 넣음** [L2107-2108]

## 6. 미결 / 다음 회의로 이월
- **예측 모델 최종 선택(물리 vs AI)** — 산림청 시계열 데이터 회신에 달림. 못 받으면 외국 시계열 데이터를 쓸지도 미정 [L1008-1020]
- **IoU 0.5 하한에 대한 대응** — 물리 모델 한계(0.5 안팎)를 논문 근거로 설명할지, AI로 올릴지는 예측 모델 결정에 따름 [L1043-1060]
- **RAG 지표 하한선 수치** — 기존 근거를 확인하는 중 [L1895-1908]
- **위험도 2순위 시점(P8) 병기 여부** — P5가 1순위이고, 하나로 가자는 의견(황승준)이 있음 [L612-628]
- **토지피복지도 사용 여부** — 필요성 의견이 엇갈림 [L45-77]
- **프로토타입 세부 범위와 PPT 분담** — 다음 회의에서 임성민의 변경 목록을 보고 결정 [L2878, L3214-3230]
- **지도 API 선택(OpenMapTiles vs 네이버)·도로·철도 데이터** — 네이버는 유료이고, 공모전 예선 결과가 7일에 나오는 것으로 언급됨(녹취 불명확) [L3343-3375]
- **요구사항 추적 매트릭스 포함 여부** — 시간이 남으면 [L2575]
- **분석서 정리 항목** — 위험도 표시 위치, 동시다발 산불별 위험도, 이벤트 로그 위치 [L2622-2629]
- **10/2 이월분 정리**: 성능 지표 목록 → ✅ 확산 5개 + 대응 4개(안건 ⑦⑧). 위험도 정의 → ✅ 1~5점·P5·면적 가중합·산불별 산정(안건 ④). 휴먼 평가·Recall@5 근거 → 정답지 AI 작성, K는 실험으로 정함(안건 ⑧). 시간대별 확산 정확도 → 산림청 문의 결과 대기. 프로토타입 수준·담당 → ✅ 목업 보강, 임성민 담당(안건 ⑫⑬)
