## 🔑 핵심 결론 (이번 회의의 본질)

**시험 기간이라 각자 고친 PPT를 "이 정도면 됐다/안 됐다"로만 판단하고 통합하기로 했다. 페이지를 넘기며 과하거나 설명할 수 없는 내용(개발자 전용 장면, 반복 개선 이력, 과한 기술 용어, SUS 설문 등)은 빼고, 프로토타입에 빠진 신고자 정보는 근거 규정을 찾아 넣기로 했다. 검증 장은 "AI 에이전트로 UI를 검증했다"고 솔직히 쓰고, 결함은 고쳐서 "발견 → 수정 → 0건" 흐름으로 보여 준다.**

- **열람자도 위험도를 본다.** 상황 보고자는 보지 않는다. 전산 관리자는 전산 관리만 한다 [L589-622, L651-724]
- **신고자 정보 추가:** 「산불진화기관의 임무와 역할에 관한 규정」 제6조 1항에 신고자 성명·연락처를 남기도록 되어 있음 → 프로토타입 v4에 넣고, 산불 현황을 보는 모든 사용자에게 표시 [L1531-1543, L1652, L1662, L1818-1834]
- **검증 장:** UI 검증은 AI 에이전트로 했다고 명시. 결함은 고쳐서 통과시키고, 개선 항목은 상중하로 나눠 10건 정도로 줄임 [L1179-1235, L1337-1347, L1616-1648, L1870-1876]
- **빼는 것:** 개발자 전용 장면, 반복 개선 이력 페이지, MVP에서 쓰지 않을 기술 용어(어댑터 캐시·브라우저 메모리·세션 저장소 등), SUS 설문 [L289-297, L487-545, L1441-1485, L1428-1438]
- **방법론:** 수업 녹음에서 교수님이 "수업 방법론의 근간은 CBD"라고 한 것을 확인해 CBD(Component Based Development)를 그대로 쓰고 ※ 주석을 단다 [L403-428, L1969]
- **일정:** 최종 PPT 10/14(수), 발표 스크립트 10/15(목) 저녁, 발표는 **홍준서** [L1989-1996, L2192-2230]
- **개발 분담 제안:** DB 설계가 우선. 개발 때 한 명은 ELMFIRE, 한 명은 대응 제안 쪽을 맡아 병렬로 진행 [L1665, L1763-1775]

> **한 줄 요약:** PPT는 과한 내용을 빼고 설명할 수 있는 것만 남긴다. 신고자 정보와 열람자 위험도 열람을 추가하고, 검증 장은 AI 검증 사실과 결함 수정 과정을 보여 주는 쪽으로 고친다. 김지오가 통합하고 홍준서가 발표한다.

**④ PPT 검토 ② 기술 스택 · 개발자 전용 장면**
- 개발자 전용 장면(10쪽 등): 캡처하려고 **없는 시나리오를 일부러 넣은 화면**이라 **삭제** [L289-297, L481-484, L1722-1725]. 실패 화면은 "실패를 어떻게 알려 줄지 예시로 구현해 봤다" 정도로만 보여 줌. 내부 주소 등은 노출할 이유 없음 [L1737-1744]
- 지도: 네이버 지도는 대회에서 떨어질 수 있으니 쓰지 않음 [L314-315]. 지도 렌더링은 지금 쓰는 오픈소스로 [L324]
- 30m 격자: 10/10에 "뺀다"고 한 것은 **지도 표시**를 뺀 것이고, **계산 단위로는 그대로** 씀 [L327-336]
- PostGIS를 왜 쓰냐는 질문이 또 나올 수 있으니 답변을 준비하거나 바꿔야 함(황승준) [L339-340]
- 배포 칸의 GPU 서버는 AI를 탑재하겠다는 뜻(김지오). 인증은 **JWT만** 넣으면 됨. DB는 PostgreSQL로 확인 [L353-388]
- 과한 기술 용어: 황승준은 기상청 단기예보 API 어댑터·캐시, 브라우저 메모리, 세션 저장소 토큰처럼 **MVP 개발에서 쓰지 않을 것**은 빼자고 함. 질문이 들어와도 답할 준비가 안 돼 있음 [L1441-1458]. API·JWT는 남김 [L1467-1473]
- EXAONE: 김지오가 실험해 보니 성능이 매우 낮음(30%도 안 나옴). 카카오 Kanana, SKT A.X, 업스테이지 Solar 등으로 대체를 검토하자고 함 → **지금은 그대로 두고 개발 때 논의** [L449-460]
- 결론: **합의** (EXAONE 대체는 **보류**)

**⑤ PPT 검토 ③ 반복 개선 이력 페이지(26쪽)**
- 황승준: 프로토타입이 1주차인데 반복 개선 이력이 들어갈 이유가 있나. 들어간다면 수정 요구사항 쪽이다 [L490-518]
- 김지오: 다른 조 PPT를 참고해서 들어간 것 같고, 교수님 자료에서도 근거를 찾지 못함 [L527-545]
- 결론: **합의** — **페이지 삭제** [L524]

**⑥ PPT 검토 ④ 위험도 표시 · 권한별 열람 범위**
- 위험도: 산불이 둘 이상이면 산불을 눌렀을 때 그 산불의 위험도가 보이는 지금 방식으로 감(10/10 결정과 같음) [L562-583]. 색은 파랑·노랑·주황·빨강 4단계로, 산림청 색에 맞춤(김지오) [L586-587]. 별도 반대 의견은 없었음
- 전산 관리자: **전산 관리만** 하고 열람은 하지 않음. 전산 관리자는 산불을 모르는 IT 관리자 역할이고 MVP만 생각함. 한 사람이 겸하면 로그아웃 후 열람자로 다시 들어옴 [L589-622]
- 상황 보고자 화면에 산불 현황 추가: 여러 사람이 보는 정보라 문제없음 → **추가**, 추가한 내용은 빨간색으로 표시 [L625-641]
- 위험도 열람 범위: 홍준서·김지오는 위험도의 활용도를 잘 모르겠다고 함(김지오: 빼고 싶었지만 넣으라고 해서 넣음) [L685-692]. 황승준: 산불 두 개 중 어느 쪽이 더 위험한지 판단하는 정도 [L688]. **상황 보고자는 볼 필요 없음**, 열람자는 홍준서가 보게 하자는 쪽에 한 표 [L695-724]
- 결론: **합의** — **열람자에게 위험도 표시, 상황 보고자는 표시 안 함** [L720-724, L1840-1861]

**⑦ PPT 검토 ⑤ 요구사항 반영 표(44쪽, 동작·혼합·연출)**
- 표의 "혼합" 문구가 무슨 뜻인지 알기 어려움. 김지오: **규칙 엔진은 동작하지만 제안 문장은 AI가 아니라 미리 만든 템플릿**이라는 뜻 → 문구를 고침 [L770-780, L844-847]
- 김지오: 이 표는 개발 전에 프로토타입이 어느 정도 구현됐는지를 **비율로 보여 주는 것** [L864-868]. 진화·대피 제안 F-15~F-28은 주황(혼합)으로 칠함 [L829-837]. 순서는 동작(100%) → 일부(혼합) → 미구현(연출) [L874-878]
- 황승준: "AI 제외"는 아직 AI를 탑재하지 않은 부분을 표시한 것으로 이해함 [L1238-1256]. 동작 수를 줄이고 순서를 바꿈(녹취상 숫자는 불명확) [L1262-1266]
- 결론: **합의**

**⑧ PPT 검토 ⑥ 근거 창 문구(33쪽)**
- 황승준: "원문 전체는 열람 권한이 있는 내부 자료로 따로 둔다"는 문장을 이해할 수 없음. 원문 보기는 10/10에 프로토타입에서 빼고 개발 때 여유가 있으면 하기로 했음 [L963-995]
- 김지오: 근거 창의 요약도 AI가 만드는 것이라, **원문을 직접 볼 수 있어야 사용자가 안심**함 [L1043-1050]. 황승준도 요약이 AI 생성이라는 점을 그제야 인식하고 동의 [L1047-1059]. AI는 원문을 그대로 잘라 보여 주기 어렵고 도구를 붙여야 함 [L1062-1063]
- 결론: **합의** — 문구를 "근거 창은 **AI 요약**을 보여 주며, 관련 매뉴얼 원문 문서는 **연결하여 열람할 수 있도록 한다**"로 바꿈. 원문 연결은 개발 때 후순위로 진행 [L1004-1013, L1065-1086]

- 결론: **합의** — **v4에 신고자 정보(성명·연락처·신고 기관명)를 넣음**, 근거 문서와 출처 링크·캡처를 메모로 남김 [L1539-1543, L1652]. 산불 현황을 보는 **모든 사용자에게 똑같이 표시**(열람자도 포함) [L1818-1834]

**⑩ PPT 검토 ⑧ 검증 장(UI · UX)**
- 김지오: 원래 UI 검증만 있었는데, 교수님이 수업에서 "UI 검증을 기본으로 하되 가능하면 UX 검증도"라고 해서 **사용성 검증**을 넣음. 검증 항목은 AI에게 제안받음 [L1156-1160]
- UI 검증은 AI 에이전트로 했음 → 교수님이 "직접 했느냐"고 물으면 답할 수 없으니(황승준) **AI로 검증했다고 솔직히 적음**: "UI 검증은 상용 에이전트를 활용해 설계·실험·검증을 진행하였음" [L1179-1235]. UX는 사용자 편의라 사람이 했어야 함(김지오) [L1198-1199]
- 권한별 화면: 의미를 알 수 없는 "13개 요소" 대신 **"4개 권한에서의 화면 확인"**으로 [L1269-1300]
- UX 결함(예: 역할 전환 후 발화 위치 입력 표식이 남음): 우리가 고쳐서 내야 하는 것 → **고쳐서 다 통과시키고 v4를 만듦** [L1337-1347]
- 황승준: UX 검증이 프로토타입 검증에 들어가는 것인지 의문 [L1350]. 김지오: 원래 프로토타입에서 하지 않지만 교수님이 말했으니 넣음 [L1356-1357]
- 분량: 너무 많은 걸 검증해서 사람 손을 거쳐야 발표할 수 있음(황승준) [L1400-1407]. **SUS(시스템 사용성 척도) 설문은 뺌** [L1428-1438]. 추가 시나리오 페이지도 빼고 싶다는 의견(황승준) → 지울 칸은 색으로 표시 [L1592-1612]. 개선 항목 옆의 SP(스프린트) 표기는 AI가 개선 계획을 스프린트에 배치한 것 [L1381-1391]
- 흐름: 황승준 제안 — "AI 에이전트로 검증 → 결함 4건 발견 → 고침 → 0건"처럼 **고치는 과정을 보여 주는 것**을 교수님이 좋아할 것 [L1616-1633]. 김지오 동의 [L1629]
- 사용자 편의 개선 항목 15건은 많음 → **상중하로 나눠 10건 정도**로 줄이고 상만 고침 [L1648, L1870-1876]
- 결론: **합의**

**⑪ PPT 검토 ⑨ MVP 로드맵 · 종료된 산불 안내 · 수정 표시 규칙**
- MVP 로드맵(49쪽)을 마지막에 두는 구성이 좋음. 방법론 화면에서는 왜 애자일을 택했는지와 순서만 말하고, 마지막에 MVP 스프린트로 마무리(황승준) [L1519-1556]
- 종료된 산불: 예측 버튼만 비활성화되므로, 옆에 **"종료된 산불은 예측할 수 없습니다"**를 빨간 글씨로 상시 표시 [L1904-1923]
- PPT 수정 표시: **수정·추가 = 빨간색, 삭제 = 초록색**(취소선이 없어서) [L641, L1747-1760]. 캡처는 **바뀐 것만 다시** 땀 [L1707-1713]
- 결론: **합의**

**⑫ 개발 분담**
- 황승준: 이제 DB 설계를 할 때다. **DB 설계가 우선**이고, DB 설계 한 명·ELMFIRE 한 명이 병렬로 진행해야 함 [L1665]
- 개발 때 둘 다 ELMFIRE를 하는 건 손해 → **한 명은 대응 제안(제안서) 쪽, 한 명은 ELMFIRE 쪽**을 맡는 게 개발·통합에 가장 편함(황승준) [L1763-1775]. 홍준서 "네" [L1766]
- 결론: **합의**(방향) — 구체적 담당자는 회의록에 명시 없음

**⑬ 다음 주 일정**
- 다음 주는 중간고사 → 금요일 정기 회의는 하지 않을 것 같음(황승준) [L1559-1562]. 다음 주에 **수정 프로토타입**을 제출해야 함 [L1580-1583]
- 다음 주 월요일 회의는 필요하면 **비대면, 4시 반**. 바뀌면 금요일에 다시 정함 [L1668-1703]
- 김지오: 금요일에 다 정해서 **주말 안에 마무리·제출**하는 게 가장 좋음 [L1684-1685]
- 결론: **합의**

**⑭ AI 경진대회 제공 환경 · AI 도구**
- 1차 교류회 발표는 없어짐(빨리 마감됨). 홍준서: 목적은 피드백이니 다행 [L1999-2016]
- 김지오가 대회 사이트 계정 정보를 공지에 올림 → API·데이터 신청 가능. **지원은 90일**이고 중간에 떨어지면 더 일찍 사라짐 [L2029-2037]
- 황승준: **필요한 데이터를 빨리 받아서 저장**해 둬야 함. 11/3 상세 보고서 제출 전까지 [L2039-2045]. 김지오: 문제가 생기면 서약서를 쓴 자신이 책임지므로 **주의해서 사용**해 달라 [L2048-2049]
- AI 도구: 김지오의 유료 AI 구독이 11/13까지 → 개발 완료 목표(11/20)에 맞춰 그때까지 최대한 활용하자. 최종 보고서 때는 함께 비용을 모아 쓰는 안도 나옴 [L2056-2079]
- 결론: **합의**

**⑮ 발표자 · 통합 · 마감**
- 발표: 원래 김지오 차례지만 바빠서 **홍준서**가 맡음 [L1989-1996]
- 황승준: 기술 스택 선정 이유(PostGIS·DB·서버 등, LLM 제외)를 **발표 대비용으로 따로 정리**해 내일까지 공유. PPT에는 넣지 않음 [L1985-1986, L2165-2174]. 자기 부분은 최종본에 직접 덮어씀 [L2022]
- 통합: **김지오** [L2026]. 순서 — ①임성민: 캡처·검증 수정 ②홍준서: 개요 합치기 ③요구사항 합치기 → **제출용 PPT** + **발표 스크립트** [L2152-2183]
- 마감: **최종 PPT 10/14(수)**, 김지오가 통합해 밤에 넘기면 황승준이 제출 [L2192-2214]. **발표 스크립트는 10/15(목) 저녁** [L2196, L2224]
- 결론: **합의**

**⑯ 주간 보고**
- 주간 보고에서도 발표하는지, 1:1 면담인지 확실하지 않음 [L2250-2266]
- 황승준: 주간 보고서용 스크립트를 만드는 **프롬프트를 만들어 공유**하자고 제안 [L2269]
- 결론: **보류** — 방식 확인 필요

## 4. 결정사항
- **열람자도 위험도를 본다. 상황 보고자는 보지 않는다** — 열람자는 산불 현황을 보는 역할이고, 보고자는 위험도가 필요 없음 [L695-724, L1840-1861]
- **전산 관리자는 전산 관리만, 열람 없음** — MVP에서 징검다리 역할만 함 [L589-622]
- **상황 보고자 화면에 산불 현황 추가** [L625-641]
- **신고자 정보(성명·연락처·신고 기관명)를 v4에 추가, 산불 현황을 보는 모든 사용자에게 표시** — 「산불진화기관의 임무와 역할에 관한 규정」 제6조 1항 [L1531-1543, L1652, L1818-1834]
- **근거 창: AI 요약을 보여 주고 관련 매뉴얼 원문은 연결해 열람할 수 있게 한다(개발 때 후순위)** — 요약도 AI가 만드는 것이라 원문 확인이 필요 [L1043-1086]
- **방법론: CBD(Component Based Development) 표기 + ※ 주석** — 수업 녹음에서 교수님 설명 확인 [L403-428, L1969]
- **빼는 것: 개발자 전용 장면, 반복 개선 이력 페이지, MVP에서 쓰지 않을 기술 용어, SUS 설문** — 설명할 수 없거나 근거가 없음 [L289-297, L487-545, L1428-1485]
- **기술 스택: 인증은 JWT, DB는 PostgreSQL(PostGIS), 네이버 지도는 쓰지 않음, 30m 격자는 계산 단위로만** [L314-388]
- **요구사항 반영 표: 혼합 = 규칙 엔진 동작 + 제안 문장 템플릿, 동작→혼합→연출 순서** [L770-878]
- **UI 검증은 AI 에이전트로 했다고 명시, 결함은 고쳐서 통과시키고 "발견 → 수정 → 0건" 흐름으로, 개선 항목은 상중하로 10건 정도** [L1179-1235, L1337-1347, L1616-1648, L1870-1876]
- **종료된 산불: 예측 버튼 옆에 "종료된 산불은 예측할 수 없습니다" 상시 표시** [L1904-1923]
- **PPT 수정 표시: 수정·추가 빨강, 삭제 초록. 캡처는 바뀐 것만 다시** [L641, L1707-1760]
- **개발 분담 방향: DB 설계 우선, 개발 때 ELMFIRE 1명 + 대응 제안 1명 병렬** [L1665, L1763-1775]
- **대회 제공 데이터는 빨리 받아 저장하고 주의해서 사용** — 지원 90일, 탈락 시 사라짐, 법적 책임 문제 [L2036-2049]
- **발표 홍준서, 통합 김지오, 최종 PPT 10/14(수), 발표 스크립트 10/15(목) 저녁** [L1989-2230]
- **다음 주 월요일 회의는 필요하면 비대면 4시 반** [L1668-1703]

## 6. 미결 / 다음 회의로 이월
- **예측 모델 최종 선택(AI vs ELMFIRE)** — 이번에도 따로 논의하지 않음. 다만 개발 분담은 ELMFIRE를 전제로 이야기함 [L1665, L1763-1775]
- **예측 성능 하한 미달 가능성** — 하한선은 그대로 두기로 했지만 대응 방안은 정하지 않음 [L40-53]

- **다음 주 회의 여부·방식** — 중간고사, 필요하면 월요일 비대면 [L1559-1703]
- **주간 보고 방식** [L2250-2266]
