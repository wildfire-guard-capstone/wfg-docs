- 기능 규모 감각: 요구사항 명세서 기준 기능 11~12개 정도가 적당하므로 걸러낼 것 [L27-33]
- 유스케이스는 기능을 잘게 쪼개지 않고 **액터 단위로 크게 묶어** 정리 [L487-494, L1272-1283]
- 이후 산출물은 PPT(요구사항 명세서 발표 자료): 기능 요구사항·유스케이스 모델·클래스 다이어그램·관계형 DB·시퀀스 다이어그램 등 프로토타입 전까지 전부 작성 [L1306-1341]

> **한 줄 요약:** 4개 시안이 큰 틀에서 수렴했음을 확인하고, 47개 기능을 초록/노란/제외로 전수 분류해 기능 목록을 확정했으며, 다음 단계(PPT·유스케이스·다이어그램)는 김지오가 AI로 초안을 만들어 4분할 분담하기로 했다.

## 3. 안건별 논의 요약

**① 화면 시안 발표 — 4안이 큰 틀에서 수렴**
- **황승준**: 사용자 용어를 '통합 지휘권자'로(지자체장, 단계 따라 상향). 위험도 점수(예: 87점)+매뉴얼 출처를 한 묶음으로 표시. 지도에 대피 장소·도움 요청 기관(경찰청·소방청 등). 투입/보유 헬기 등은 계산 불가하므로 지휘자가 **상황 입력**하면 제안서가 구체화되는 구조. S1~ 의사결정 제안서 + 근거 클릭. 확산 폴리곤·좌표 **갱신 버튼** [L298-314]
- **임성민**: 발화 지점에 산불 발생 정보. 주변 유관기관(사무소·파출소·소방서) 클릭 조회 + 개수 표시(산림청 통합관리시스템 참고). 체크박스 레이어. 우측에 진화·대피 요약(S1~ 기반). 플로팅 버튼 **AI 어시스턴트** [L353-370]
- **김지오**: 로그인부터 구현. 담수지(저수지)·마을 표시. 확산 예측 1시간 단위 재생 + 3D. 조건(풍향 등) 변경 시 예측 갱신. 연락처 모음, 거리 표시, 진화 우선 보호대상 하이라이트. **AI 어시스턴트를 비서·보좌관 개념**으로: 질문("헬기 몇 대 투입 근거는?")뿐 아니라 **정정**("박곡리 대피 완료" 입력 → 상황 정정 확인 → 대응 제안 갱신)까지. 모든 출력에 근거 표시 [L386-412]
- **홍준서**: 지도에서 발화 위치 지정 → 시간 입력 → 예측 실행 → 위험 지수·대응 보고서 생성. **시간 슬라이더**로 확산·위험 지역·보고서 내용이 함께 변동. 기상·지형 체크박스 레이어. 우측 하단 챗봇(추가 질문용) [L437-466]
- 결론: **합의** — 대응 제안 쪽은 4안이 거의 동일했고 [L939-943], 이 수렴을 기준으로 기능표 확정 진행.

**② 상황 관리 기능군**
- 논의: 로그인은 간단히(관리자가 계정 할당, 회원가입 없음. 외부 유출 방지 목적) [L66-88]. 산불 발생 접수 정보는 사용자가 입력하는 게 아니라 **받아오는 것**으로 — 시연 때 "여기에 신고가 접수됨"으로 시작하는 그림이 자연스러움 [L109-116, L498-528]. 이력 관리는 필요성 불확실 [L141-154].
- 결론: **합의** — 로그인·산불 발생 접수 정보 조회 포함, 이력 관리 보류.

**③ 현장 상황 입력·관리자 기능**
- 논의: 현장 상황 입력·수정(진화율·대피·부상 등)은 자원 배분 능력이 없는 우리 시스템에서 14개 항목 제안을 살리는 입력이지만, 메인 기능은 아님(홍준서·임성민 모두 "부가적") [L531-573]. 자원 기초정보(보유 헬기·차량·인력) 등록·갱신은 **관리자** 역할로: 관리자 = ①기초정보 갱신 ②계정 발급, 두 개만. 시연 영상에는 미포함. 데모는 가짜 데이터 사용 [L588-628].
- 결론: **합의** — 현장 상황 입력은 노란(보류, S1~S7 쓰다가 막히면 추가), 관리자 기능은 비기능 요구사항 성격으로 유지.

**④ 지도 레이어·표시 정보**
- 논의: 레이어 중 연료·지형 제외, 기상(풍향·풍속)·시설·인구·도로·기관 포함 [L635-666]. 지도 표시 대상은 마을·시설·유관기관·담수지·취약시설·문화재 — 담수지는 헬기가 물을 퍼나르는 데 실제로 확인하는 정보라 포함 [L723-729]. 상세 정보는 **위치·거리만**(주소·전화번호는 평가에 무의미) [L781-802]. 자원(헬기·인력·차량) 보유/투입/대기 현황도 지도에 표시 — 단계 격상 시 추가 요청 판단에 활용 [L819-843].
- 결론: **합의** — 위 기준으로 조회류 항목 통합·확정.

**⑤ 확산 예측 기능군**
- 논의: 시간 경과에 따른 확산·대응 변화 표시는 시연의 핵심이라 필수 [L863-867]. 조건(풍향 등) 변경 재예측도 시연 가능한 기능으로 포함 [L876-885]. 예측 결과 텍스트 요약은 지도로 대체(제외), 3D도 제외 [L886-914].
- 결론: **합의**.

**⑥ 대응 제안 기능군**
- 논의: 대응 제안 생성·갱신·상세 조회는 당연 포함 [L917-920]. 세부 기능 중 '변경 사항 조회'는 **동일 시간대에서 정정 전후 비교**용(시간대 간 비교가 아님) [L996-998]. 제안 판단 기록·취소는 사람이 직접 하는 게 아니라 AI 어시스턴트를 통해 정정하는 쪽 [L1010-1029]. S1~S7×(진압·대피) 세부 14줄은 기능으로 나열하지 않고 **"진화 판단 대응 방안 / 대피 판단 대응 방안" 2개로 통합** [L1203-1230]. 대응 제안 출력 형식이 지저분해서 다듬어야 함 [L1162-1170].
- 결론: **합의** — 생성·갱신·조회 + 매뉴얼 확인 초록, 변경사항 조회·판단 기록은 노란.

**⑦ '근거 부족' 표시 방침 변경**
- 논의: 기존 출력 계약은 근거 없으면 "근거 부족"을 달고 출력하기로 했으나, 교수님 PPT가 "모순·근거 없음 위험 요인은 **차단 규칙으로 관리**"라고 명시 → 차단이면 굳이 표시하고 내보낼 이유가 없다 [L1076-1114].
- 쟁점: 차단하면 시연에서 RAG의 안전장치를 보여줄 수 없지 않나(황승준) → 별도 시나리오로 설명 가능(예: 헬기 정보가 없을 때/넣었을 때 비교) [L1126-1146].
- 결론: **합의** — 근거 부족 항목은 표시하지 않고 내보내지 않음(차단). 시연은 별도 시나리오로.

**⑧ AI 어시스턴트(QnA) — 이월 쟁점 해소**
- 논의: RAG를 쓰므로 무리한 요청("소방관 10명 배치해")에도 규정 근거로 거절 답변 가능 [L1038-1039]. 추가 질문 용도(홍준서), 정정 인터페이스 겸용(김지오).
- 결론: **합의** — **AI 질의응답(43번) 초록으로 포함**, 세부 파생 기능(44~47번)은 노란 [L1252-1266]. → 9/24 회의의 P1 미결 "QnA 포함 여부"가 **포함**으로 확정.

**⑨ 다음 산출물(PPT)·작업 분담**
- 논의: 교수님 PPT 요구 항목(기능 요구사항, 유스케이스 모델, 클래스 다이어그램, 관계형 DB, 시퀀스 다이어그램, 비기능 요구사항 등)을 프로토타입 전까지 전부 작성 [L1306-1341]. 성격이 달라 개인별로 나누면 안 이어질 우려 → 김지오가 AI로 기획서+오늘 확정 표+교수님 PPT를 넣어 **통합 초안 생성 후 4분할** [L1346-1363]. 핵심(기능~시퀀스)은 화요일까지 [L1357-1360].
- 결론: **합의**.

- **산불 발생 정보는 입력이 아닌 수신** — 시연은 "신고 접수됨"으로 시작 [L503-528]
