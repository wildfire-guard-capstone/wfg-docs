## 1. 서비스 개발 부문 (이어서)

### ① 케이스 셰어룸(CSR) — 보이스피싱 탐지 이후 대응 지원 (우리의 사회적 책임 / 한형준)
**발표 요지**
- 보이스피싱 **탐지 이후** AI가 통화 내용을 분석해 사기범의 요구와 대화 맥락을 정리 → **은행 직원의 상황 파악·대응을 돕는 B2B AI 솔루션**, 고객에게는 송금 전 재판단 기회 제공
- 문제: 위험을 탐지해도 직원이 고객 상황(맥락)을 모르면 설득에 실패 — 은행의 탐지·경찰서 방문 권유에도 누적 15억 6천만 원 피해 사례
- 구현: 은행 직원·고객용 UI/UX, GPT API 기반 사건 요약
- 향후 계획
  - 금융기관 이상거래 탐지(FDS)·거래 정보 API 연동 협의
  - 송금 시도 시 챗봇이 자동 실행되는 **송금 전 방지턱**, 문자·앱 푸시
  - Llama·Gemma 등 공개 모델로 **폐쇄망 AI**, 파인튜닝 + RAG
  - 통화 데이터·개인정보 법적 검토, 온디바이스 AI, 규제 샌드박스·실증 특례
  - 앱 내 상담 통화, STT 요약, 은행 실무자 자문으로 UI 개선
- 질문: 은행·통신사·법률/보안 전문가·금감원 인터뷰를 적극적으로 요청하는 방법

**피드백**
- **박지은**: 경찰청도 유사 서비스로 2024년 대통령상 수상 — 비공개 통화 녹음·목소리 학습 데이터 보유. 그보다 무엇이 나은지 설명 필요. **금융 정보 연동은 어려울 것.** 통신사·정부 서비스 대비 시장성·실효성 보완
- **박지은(추가)**: 사기범은 피해자를 고립시켜 연락할 틈을 주지 않음 → 실제로 작동하는 시나리오인지 검토
  - 팀 답변: 앱 팝업 버튼을 누르면 통화가 끊기고 상담사로 연결되는 방식 구상 → 기술은 가능할 수 있으나 법적 가능성은 검토 필요, 피해자가 그 버튼을 누를지가 관건
- **멘토(공적 마스크 앱 개발 경험)**: 토스는 낯선 계좌로 큰 금액 송금 시 질문을 여러 개 띄움. **어느 시점(통화 중/송금 시)에 개입할지** 선명하게. 이해관계자가 너무 많은 어려운 길 → 사기 사례 **시뮬레이션으로 미리 경험하는 '백신' 컨셉**이 더 쉽고 발표하기도 좋음
- 팀 입장: 탐지는 이미 토스·은행·통신사가 잘함. 우리는 **탐지 이후 은행 담당자의 정보 수집·대응**을 돕는 LLM 브리핑·가이드

### ② 피해있다 — 재난 피해 현장조사 지원 AI (복구보호팀 / 이성호)
**발표 요지**
- 주택 재난 피해 증가(작년 4천여 동, 올해 8월 거제 650mm 이상 강우)
- 피해 신고 후 **현장조사가 의무**인데 인력 부족
- **현장 조사 실무자 인터뷰** 결과
  1. 인력 부족 — 같은 과 다른 업무 담당자까지 동원
  2. 현장과 전산 분리 → **이중 입력**
  3. 침수 정도를 **주관적으로 판단** → 애매하면 재방문, 주민 이의 제기
- 서비스(현장조사 공무원용)
  - 침수 흔적 촬영 가이드(VLM)와 판단 근거 제시
  - 회차·지역마다 다른 법령 기준을 반영한 **체크리스트**(RAG + LLM + 규칙 엔진)
  - 조사 진행 **현황판**
  - 조사 완료 후 LLM으로 결과 정리 → NDMS 입력 초안
- 기대 효과: 재방문 감소, 동원 인력도 같은 기준으로 조사, 이중 입력 감소

**피드백**
- **박지은**: 기획서의 **데이터가 잘못됨** — 플랫폼의 기존 침수 데이터는 특정 지점 정보라 주택 피해에는 쓸 수 없음 → 목적에 맞는 데이터 확보 필요. NDMS가 불편하면 NDMS 개선이 답일 수도. 시나리오·데이터 사용·판단 방식을 명확히. 공무원용이면 **비즈니스 모델**도 고민
  - 팀 답변: 신고자 대부분이 어르신이라 시민 사진 신뢰도가 낮아, 현장조사 공무원 지원에 집중
- **박수영**: 피해 인정에 필요한 사진의 **최소 요건**을 정해 촬영을 안내하는 기능 고려
- **소장(?)**: AI 결과는 초안이고 **최종 결정은 사람**이 하도록. NDMS는 **행정망과 인터넷망이 분리**돼 있어 바로 연동하기 어려움 → 보안 고려

### ③ 리체크 — 고령층 모바일 금융 레이더 (이근원 PM)
**발표 요지**
- 은행 창구 감소, 독거 고령 가구 증가, 고령층 모바일 금융 이용 급증
- 송금 **전** 순간에 흩어진 맥락 정보를 대조해 평소와 다른 점·불필요 지출·이상을 안내
  - 예: 스미싱 문자 → 거래 기록 + 연락처 + 금융보안원 주의 사례 대조 → "기존 연락처·거래와 다르고 주의 사례에 해당, 딸에게 확인해 보세요"
- 합성 데이터 테스트: 청구 50건 중 거래 기록만 볼 때 21건 놓침 → 연락처 추가 시 약 절반 → 공식 안내문(관리비 인상 등)까지 대조 시 **불필요 알림 100% 해소**
- 질문: FDS가 못 보는 모바일 맥락 정보를 API로 제공하는 사업화의 차별성, 종합 금융 에이전트 vs 범위 축소

**피드백**
- **박지은**: 고령자 금융 피해라는 문제는 명확함. 다만 어르신은 에이전트·리포트를 보기 어렵고, 금융사가 아니면 데이터 확보가 어려움 → **실제 수요자(어르신 본인? 자녀?)를 구체화**. 확장성은 언급하되 챌린지는 **사회 현안 해결**이라 고령자 문제에 집중
- **박수영**: 어떤 맥락 데이터를 쓸지 **리스트업이 최우선**. 문자 전체 열람 등은 **개인정보보호법상 최소 수집·목적 제한 위반**으로 과태료 위험 → 해결할 문제와 필요한 최소 정보를 분명히
- **정덕우**: 마이데이터 활용은 사업자 요건 등 문턱이 높음 → 사전 검토
- **멘토(?)**: 카카오 등 대형 금융 서비스와 경쟁이 어려움 → **타깃을 좁힐 것**

### ④ 모두의 한 걸음 — 재난문자를 '지금 할 일' 카드로 (발달장애인·느린 학습자 대상)
**발표 요지**
- 실제 재난문자(예: 8/31 성남 하천변 저지대 대피)에 어려운 낱말이 많아 발달장애인·경계선 지능인은 행동을 판단하기 어려움
- 장애인 실태조사: 재난 시 행동한다는 응답 전체 63.6% vs 지적장애 29.8%, 자폐성장애 19.2% / 대피소 인지 7.5%, 8.9%
- 새 경보를 만들지 않고 **원문은 그대로 두고** 쉬운 **행동 카드**를 붙임 (전문가·당사자 사전 검수)
  - 대피 지시 시 장소까지 안내, 말하기 어려우면 **도움 요청 카드·119 문자**
  - 불확실한 문자는 카드 없이 원문 + 보호자/119 버튼
  - **AI는 글을 쓰지 않고 분류만**, 규칙 우선·애매할 때만 AI
  - 카드는 기기에 **로컬 저장** → 통신 두절 시에도 표시
  - 보호자 등록 장소 → 없으면 근처 공공 대피소 순
- 10월 실기기 실험·초안 10종, 행안부 등에 협의 요청, 향후 취업 연계 플랫폼 사업화
- 질문: 재난문자 테스트용 **공기계 지원** 여부

**피드백**
- **박지은**: 공기계 지원은 **없음**(지원은 클라우드만). 발달장애 아동 사업 3년 경험상 **자폐성 장애는 타깃에서 제외**해야 함(읽고 이해하기 어렵고 보통 보호자와 함께 있음) → **경계선 지능인** 등으로 타깃 명확히. 위치 기반이면 **AI가 불필요**할 수도. 사전 조사 근거 보강
- **박수영**: 느린 학습자 콘텐츠를 만드는 비영리 **피치마켓**과 협업해 전달 방식·검증
- **소장(?)**: 폭우로 공공데이터상 대피소가 침수될 수 있음 → **실시간 정보 업데이트** 방안 필요
- **멘토(?)**: 앱을 여는 것 자체가 어려울 수 있음 → 기본 탑재 기능 활용·알림 방식 고민

## 2. 아이디어 발굴 부문

### ⑤ 나의 세금 영수증 (블랙스 / 김도연, 수습 회계사)
**발표 요지**
- 마트도 영수증을 주는데 수백만 원 세금엔 명세서가 없음 → 세금 사용처를 **체감하지 못하는 것**이 조세 저항의 핵심 요인
- 열린재정 등은 정부 부처 기준이라 내 삶과 연결 안 됨
- 기능
  - **나의 세금 영수증**: 납부액 직접 입력(국세청 연동은 보안상 어려움) → 예산 비율로 역산해 분야별 금액 표시, 클릭 시 세부 사업·정책 링크
  - **우리 동네 세금 지도**: 지방 사업을 지도 핀으로(예: 이 도서관에 내 세금 4,500원), 시민 피드백·이상 신고
  - 내 세금 혜택 찾기, 주민참여예산 연동 **세금 투표**, 전년 대비 변화
- 목표: 납세자를 정부의 '주주'처럼 → 효능감 증가, 조세 저항 감소

**피드백**
- **정덕우**: 국세·지방세를 어떻게 나눠 표현할지 정리(팀: 국세는 종합 영수증, 지방세는 지도). 담배세 일부가 소방안전교부세, 주세 일부가 교육세 등 재미 요소 있음. **컨셉을 명확히** — 재미·납세 보람인지, 내 주변 기여 체감인지
- **박지은**: **챌린지 주제(재난·사회 현안·위기 대응)에 맞는지**부터 설명해야 함. 생활 편의처럼 들림. 수요자가 누구인지(국세청?)
- **소장(?)**: 개인보다 **공공기관 홍보용**으로 쓰일 것 같음. 시의성(대기업 세수 등) 반영
- **멘토(공적 마스크 앱 개발 경험)**: **노선을 잘 정할 것**. 예: 고액 상습 체납자 총액(개인 단위는 명예훼손)이 우리 동네 사업에 얼마나 됐을지 같은 위기의식·고발형, 또는 대기업 법인세의 사회 기여 같은 긍정형
- **멘토(?)**: 공공·동네보다 **내 가족·지인이 받은 혜택**(아이 학교 의자 교체 등)으로 효능감을 주면 더 재밌음

### ⑥ 블루가드 — 실시간 조위 기반 연안 침수 예방·대응 (김주인, 임현우)
**발표 요지**
- 대조기·백중사리에 해수면 상승 → **비가 오지 않아도** 도로·차량 침수
- 기존 한계: 폭풍해일 특보는 예비특보가 없어 대비 시간 부족, 조석 예보는 수치뿐이라 주민이 위험 판단 어려움, 지자체 대응 시점 편차
- 서비스: 조위·지도 API 수집 → **예측값과 실측값 비교로 침수 위험 5단계** 분류 → 지도형 상황판(지자체·주민)
- 프로토타입: 전남 진도군(지역별 조위·위험 단계, 지점 상세, 월별 위험 달력)
- 로드맵: 진도 구축 → 전국 연안 → 지자체 연동 사전 알림

## 4. 3부에서 반복된 핵심 포인트

1. **기존 서비스와의 차별점** — 경찰청·통신사·토스(보이스피싱), 농업e지(농사), 기상청 특보(연안 침수) 등 이미 있는 것과 비교
2. **타깃을 좁히고 명확히** — 자폐성 장애 제외, 고령자 본인 vs 자녀, 대형 금융사와 경쟁 회피
3. **챌린지 취지(재난·사회 현안·위기 대응) 적합성**을 도입부에서 설명 — 세금 영수증, 농사 달력이 지적받음
4. **개인정보·법적 검토** — 최소 수집·목적 제한, 마이데이터 요건, 통화 개입의 적법성
5. **공공 시스템 현실** — 행정망 분리, 금융 정보 연동 불가, 공기계 등 클라우드 외 지원 없음
6. **AI는 초안·지원, 최종 결정은 사람** / 규칙 우선, AI는 애매할 때만
7. **데이터 근거** — 목적에 맞는 데이터인지, 원천이 공신력 있는 기관인지, 예측 기준값이 명확한지
8. **확산 전략** — 한두 곳 실증 → 소관 부처 접촉, 기업 캠페인·오픈이노베이션 활용
9. **인센티브·효과 환산** — 사용자에게 추가 업무가 되지 않도록, 안전 가치를 비용으로 환산
