## 2. 팀별 발표 & 피드백

### ① 홍수 대응 의사결정 지원 (1인 개발)
**발표 요지**
- 출발점: 오송 지하차도 참사 — 위험 수위·통제 요건을 충족했지만 통제하지 않아 14명 사망, 실무자 약 45명 기소
- 실무자에게 **통제 판단 근거**를 제공하면 사고와 실무자 부담을 줄일 수 있다는 가설
- 공공데이터(강우·수위 등) 기반 앱, 시기별 구성
  - 장마 전: 시설 점검 / 장마 중: **관제 보드**(실시간 API로 위험 시설 확인) / 장마 후: 대응 **적정성 평가**
- 개발 중점: 다요인 등록으로 **과잉 경보 줄이기**, **과거 사건 재구성·시뮬레이션**, 자연어로 정보를 찾는 **에이전트**
- 질문: 가정한 현장 흐름이 맞는지, 공공기관 사용자 검증 기회, 에이전트 성능 개선

**피드백**
- **박지은**: 경보 흐름·수위 기준은 정부 지침·연구원에서 이미 규격화돼 있음. 오송 사고의 핵심은 알림 부재가 아니라 환경부–경찰청–지자체–현장 사이의 **정보 분절과 병목**, 운전 중 재난문자를 볼 수 없는 특수성. **지자체에 전화해 실무자 인터뷰**를 요청하면 대부분 응해줌. 모니터링 시스템은 이미 존재하므로 사고가 왜 났는지부터 볼 것. 홍수 주제 팀이 여럿이라 **차별점** 고민 필요
- **소장**: 통제 기준은 법·지침이 있으니 서비스가 그에 맞는지 정확성 검토. **효과성**(사고 예방, 현장 대응력 향상, 업무 감소 등)을 구체적으로 보완
- **박수영**: 재난 판단은 **누가 결정하고 누가 책임지는가**의 문제라 단순 자동화는 어려움. 최종 판단 주체가 필요. 과거 실패에서 배우는 **시뮬레이션 고도화**가 차별점 — 공무원의 예측·판단을 지원하는 방향으로
- **정덕우**: 경기도는 경기연구원이 이미 **디지털 트윈 기반 홍수 예측 모델**을 보유. 분절 데이터 통합은 이미 많이 돼 있음 → 그 데이터로 무엇을 할지 **뾰족하게**

### ② 녹음길 — 겨울 보행 결빙 위험 지도 (조윤호)
**발표 요지**
- 75세 이상 손상 입원 환자의 72.5%가 추락·낙상, 도로 결빙 교통사고의 78%가 12~1월
- 기상·적설·**그늘(일조·건물 높이)** 정보로 결빙 가능성이 높은 보행 구간을 새벽에 미리 산출
  - 예: 6m 건물 그림자 — 여름 한낮 약 1.5m vs 겨울 오전 9시 약 26m (약 17배)
- 대상별 제공: 주민(결빙 지도·우회 경로), 제설 담당자(제설 우선순위), 보호자(부모님 동네 등록 → 아침 6시 알림)
- 향후 주민 경험·현장 실측으로 정확도 향상
- 질문: 계절성 서비스의 한계 극복 사례, 실제 결빙 비교를 위한 협업 기관

**피드백**
- **이준수**: 결빙은 어느 정도 예측 가능하고 지자체가 이미 **상습 결빙 구간**을 관리. 주민은 매일 다니는 길을 잘 앎 → **누구에게 유용한지** 문제 정의를 뾰족하게. 지자체가 놓친 부분을 보조하는 방향이면 사계절 운영은 불필요. 열선 설치 등 실제 해결로 이어질 때 의미
- **서영경**: 그늘 지도와의 차별화 필요. 보행자보다 **염화칼슘을 어디에 뿌려야 효율적인지** 등으로 포커스 전환 고려, 지자체의 비효율·경제성 비교. 협업 기관보다 **직접 현장에 가서 실측 데이터**를 모으는 게 더 설득력 있음
- **소장**: 타깃이 노인·보호자인지 지자체인지 명확히. 예측과 실제 결빙(제설제 살포 등)의 **불일치**가 많을 수 있음 → 이용자 신뢰 문제. 긴급 대응이 필요한 지자체엔 유용
- **박지은**: 타깃에 따라 도보/도로, 담당 부서가 달라짐 → 해결하려는 문제를 명확히. 자체 모델도 명확히 설명(수분·온도 등 데이터 근거). 지도교수를 찾아가 조언받을 것

### ③ 게임 기반 청년 진로 탐색 플랫폼 (홍유성)
**발표 요지**
- 문제: 자기 적성을 모르는 청년, 취업 후 진로 전환 고민. 기존 적성검사는 지루한 체크 형식, 실무 경험 기회 부족
- 타깃: 20~30대 청년
- 퍼즐·공간 탐색·자원 배분 게임으로 문제 해결 역량 파악, 기획·창작 역량은 LLM으로 평가
- 게임 결과 → **실무 미션** 부여 (예: 개발 역량이면 오픈소스 커밋). 게임의 즉각 보상으로 동기 부여
- 향후 고용센터·대학 진로센터 연계 제안

**피드백**
- **소장**: 게임을 하면 왜 진로 탐색에 도움이 되는지 **인과 설명** 필요
- **박수영**: 게임 장르와 직무의 상관관계, 다른 게임과의 차별점이 설명돼야 함. 실제 일은 사람과의 상호작용·돌발 상황이 많은데 **현실적 시나리오**가 부족
- **정덕우**: MBTI 기반 직업 추천 등 대비 더 디테일하고 **한국적·현실적인** 직업 매칭이 되는지 조사
- **서영경**: 게임을 싫어하는 청년은 어떻게? **수요층** 정리 필요. 협력 대상(고위 공무원 등) 조정. 이력 기반 기업 매칭 같은 **포커싱** 고려

### ④ 유기동물 보호소 QR 돌봄 기록 서비스 (정석(?))
**발표 요지**
- 보호소 봉사 경험: 비슷한 외모의 개체 구분 어려움, 투약·임신·혈변 등 정보가 사람 사이에서 끊김
- **개체별 QR** → 설치 없는 모바일 웹
  - 운영진: 동물 등록, 사진·공간 정보, QR 부착, 기록·공개 범위 관리, 우선 확인 개체 파악
  - 봉사자: QR로 개체·주의사항 확인, 식사·산책·특이사항·건강 기록
  - 입양 시: 건강·투약·생활 습관을 **인수인계서**로 새 보호자에게 전달
  - 방문자: 공개 정보 확인, 임보·입양 문의, 후원
- **긴급 모드**: 대규모 구조·대피·전염병 시 개체별 이동·투약·분리 정보를 투입 인력에 전달

**피드백**
- **박지은**: 본인 관심사에서 출발해 문제·해법이 구체적, 자료도 좋음. 본선에선 **전달력** 보강, **수요·지속 가능성** 근거 추가. 포인핸드(입양 서비스)와 목적이 달라 **연계** 가능성 — 입양자는 관리 이력이 궁금함
- **박수영**: 후원 수수료 등 **비즈니스 모델** 고민, 유사 서비스와 협력해 지속성 확보 방안을 본선 발표에 담기
- **정덕우**: 대형 서비스와의 협력은 **아이디어를 뺏길 위험**도 있음 → 먼저 오픈해 이용률·유입 확인. 관찰 기준이 주관적이니 상태를 **카테고리화·UI/UX 개선**하면 경쟁력
- **서영경**: 개 외 고양이 등으로 대상 확대, AI 활용 고려

### ⑤ 재난 지원 내비게이터 (양다연)
**발표 요지**
- 계기: 재난 지원 한도가 시간이 지나며 확대됨(예: 8/21 약 1억 원 → 9/28 최대 3억 원)되지만 피해자가 직접 찾아야 함
- 기존 재난 플랫폼에 더해 **변경 추적·알림** 제공 (모바일 웹)
  - 흐름: 접속 → 인증 → 피해 정보 입력 → 결과 확인 → 이후 제도 확대·특별재난지역 선포 시 메일·문자 알림
  - 예: 주택 침수 피해자 → 선포 전 17개 지원 표시, 선포 시 해당될 5개는 '알림 예정'
- 법령 Open API 기반 매칭 엔진, 과거 데이터 검증 **재현율 약 90%, 정확도 약 95%**
- 11월 말 배포 목표
- 질문: 공공성 서비스의 **수익화**, 과거 데이터로 **미래 지원을 예측**해 안내해도 되는지

**피드백**
- **박지은**: 공공 서비스의 BM은 늘 어려움 — 내비 사례도 재난 알림 자체가 아니라 신뢰도 상승에 따른 간접 이익. 재난은 행안부 소관이나 실제 대응은 지자체. 정부 지원은 **국민비서**로 알림이 오지만 **지자체 지원은 오지 않음** → 차별점이 될 수 있음
- **정덕우**: 3.3% 환급 대행처럼 **귀찮음을 대신하는 수수료** 모델 가능. 사진으로 피해 규모를 산정해 추가로 받을 수 있는 금액을 찾아주거나, 현장 확인하는 **담당 공무원 업무를 줄여주는** 대가를 지자체로부터 받는 방안. 피해자가 스스로 피해를 입증하는 가이드가 부족한 현실을 짚은 점이 좋음
- **이준수**: 주소 기반 지자체 공고 매칭은 구현이 어렵지 않음 → **과거 사례로 실제 동작하는 시연**을 보여주면 임팩트 큼
- **박수영**: 지원 금액은 케이스마다 달라 **예측보다 정확한 정보 전달**에 집중. 95%는 낮음 — 신뢰가 핵심이라 **99% 이상** 필요. **중복 지원 불가 조건** 등 복잡한 조건까지 반영해 "이 조합이 가장 많이 받는다"까지 제시하면 사업화에도 도움

### ⑥ AI 기반 돌봄 기관 행정 자동화 플랫폼 (어스퍼시스(?) / 김훈·김영환(?))
**발표 요지**
- 팀에 현직 장애인 돌봄 종사자, 장기요양 노인복지 기관장 참여
- 사회복지사 44.6%가 과도한 행정으로 워라밸 상실, 연차도 제대로 못 씀
- 기관 대부분 유료 ERP + 엑셀·매크로로 수작업 대조
- SaaS로 급여 계산 + AI 기능
  - **부정 결제 탐지**(물리적으로 불가능한 이동 시간 내 결제 등)
  - 회의록 녹음 기록
  - 이용 시간·거리 기반 **종사자–이용자 최적 매칭**
- 질문: 민감·개인정보 DB 구축 방법, 보수적인 복지기관 진입 전략

**피드백**
- **박지은**(취약계층 지원 업무 4년): 무엇을 해결하려는지 와닿지 않음 — 업무 효율화인지 매칭인지. 바우처가 지자체·본부로 쪼개져 있고 **복지로 연계**는 개인정보·평가정보 문제로 본인도 3년 시도했으나 실패. 현실 가능성을 판단해 **잘라낼 것은 잘라내야** 결선에서 좋은 평가. 공모전은 짧게 **톡톡 전달**돼야 함
- **소장**: 통합돌봄 체계로 수요는 큼. 정부·유사 서비스 대비 **킬러 서비스 하나**에 집중
- **서영경**: 도입하면 오히려 업무가 늘 수도 있음. 누가 쓰는지, 어떤 행정을 간소화하는지 **문제 재정리**

### ⑦ 첫 살림 — 자립준비청년 생활 계획·점검 AI (팀 교태(?) / 김은지)
**발표 요지**
- 자립준비청년: 보호 종료 후 자립하는 청년, 매년 약 1천여 명, 69.5%가 혼자 생활
- 기존: 지원 정보 검색·재무 상담은 있으나 월별 생활비와 연결되지 않음

  - 누락 항목 알림(예: 관리비), 월별 잔액·부족 시점, 지출 조정·지원·추가 소득 비교

  - 예: 가용 자산 550만 원, 생활비 135만 − 자립수당 50만 = 월 85만 감소 → 7개월 차 부족, 12개월 기준 470만 원 필요
- 계산은 **규칙 엔진**, AI는 결과 설명·계획서 초안에만 사용. 공공데이터로 입력 부담 감소(출처·기준일 표시)
- Spring 서버, 플랫폼 클라우드 활용 / 10월 내 자문가 인터뷰, 사용자 검증

**피드백**
- **박지은**: 발표 흐름이 **간결하고 좋음**. **개인화** 설명 추가 — 공통 고정지출 외 개인 저축 비율 등 반영 방법
- **소장**: 왜 자립준비청년만 절약해야 하나? 실제로 쓸지 의문 → 절약을 넘어 **일자리·주거 추천** 등 지원 기능 하나 추가
- **박수영**: 일반 청년도 쓸 만함 → 왜 자립준비청년용이어야 하는지 기획 보강. **커뮤니티**(재테크·일자리·생활 팁 공유)로 활성화 고려
- **정덕우**: 인터뷰·MVP 결과를 업데이트해 공유해 달라
- **서영경**: 수요 검증, 사업화(절세 방안 등 부가 서비스) 고민

### ⑧ 나의 안전 플레이북 — 상황 맞춤형 재난 행동요령 (이치화(?), 현직 경찰)
**발표 요지**

- 평소 앱에서 **자신의 상황(자주 있는 곳, 반려동물, 반지하 거주 등)을 등록·훈련** → 데이터는 **기기 로컬에만 저장** → 실제 재난문자 수신 시 로컬 데이터와 매칭해 맞춤 행동요령 제시
- 환각 방지: **공식 안내와 AI 맞춤 안내를 함께 표시**, 최종 판단은 본인
- 100개 넘는 행안부 행동요령 → 9~10개 첫 행동으로 압축
- 반려동물 등 **행동요령의 공백**을 발견해 행안부에 역제안
- 비즈니스 모델은 고려하지 않음(공익 목적)
- 질문: GPS 등 자동 수집 범위, 안내 수위, 추가 연계 데이터

**피드백**
- **박지은**: 재난문자를 귀찮아하는 사람이 일일이 상황을 눌러 입력할지 의문. 실제 재난문자엔 층·세부 상황 정보가 없어 맞춤이 어려울 수 있음. 사용자 확보 방안 필요
- **소장**: 위치정보는 사전 동의 없이 수집 불가 → **개인정보·위치정보 법적 검토** 후 개발 (로컬 저장 방식 확인)
- **박수영**: 행안부와 공식 협력은 필수 아니지만, 행동요령 고도화까지 하려면 **행안부 연계 계획**이 드러나면 심사에 유리. 사용자 피드백을 받을 **인센티브** 설계 필요 → 서비스 + 정책 개선의 투 트랙

### ⑨ 촌수의사 — 고령·소규모 축산 농가 이상징후 초기 대응 (LMS)
**발표 요지**
- 구제역·럼피스킨 등 반복되는 가축 전염병 (대규모 살처분·보상금 영상으로 시작)
- 농장주의 54.1%가 65세 이상, 50두 미만 소규모 한우 농가가 과반, 스마트축산 지원 축소
- **멀티모달 + 축산 온톨로지** 기반 AI: 휴대폰으로 축사 영상·소리 기록 + 음성 문진 → **초기 대응 4단계** 중 하나 안내, 판단 근거, **신고서 초안**, 가까운 거점 소독시설 안내
- 한우 농가 대상 MVP(음성 문진 → 신고서 초안), 알파 테스트
- **의료 진단이 아니라** 이상징후 시 빠른 신고 행동을 안내하는 서비스
- 데이터: AI 허브 축산 데이터 등

**피드백**
- **박지은**: 목표·시나리오·해결 방식이 잘 드러나지 않음. 동물 원격 진료 관련 **법적 범위** 확인. 학습 데이터가 불명확. 서비스명에 '이상징후'를 넣는 게 명확할 수 있음. 고령 농장주용 **UI/UX 쉬움**을 보여줄 것
- **소장**: 신고 의무 기준이 있다면 **법령·지침 수준**으로 이상징후를 판정하도록 개발·검증해야 함
- **박수영**: AI 허브 발성 데이터는 정상/이상 구분 데이터가 아닐 것 → **라벨링된 학습 데이터 확보** 방안. 매일 소를 보는 농장주보다 AI가 더 잘 발견하는지 설득력 부족 → **대체가 아니라 의사결정 지원**에 초점
- **정덕우**: **가축위생방역지원본부** 실무자 인터뷰 권장. 현실 가능성이 잘 안 보이고 이슈 대응 수준으로 접근한 인상. 고위험 전염병을 다루므로 팩트 체크를 명확히 해야 함

## 3. 멘토 피드백에서 반복된 핵심 포인트

1. **문제 정의와 타깃을 뾰족하게** — 누가 쓰는지, 무엇을 해결하는지 한 문장으로. 다 하려 하지 말고 잘라내기
2. **기존 서비스·제도와의 차별점** — 이미 있는 모니터링 시스템, 지자체 관리, 경기연구원 디지털 트윈, 국민비서, 포인핸드 등 먼저 조사
3. **현장 실무자 인터뷰** — 지자체에 전화하면 대부분 응해줌. 직접 현장 실측도 강력한 근거
4. **법령·지침 준수** — 통제 기준, 신고 기준, 개인정보·위치정보, 원격 진료 범위 등
5. **AI의 역할 = 판단 대체가 아니라 의사결정 지원** — 책임 주체는 사람. 공식 정보와 AI 결과 병기
6. **정확도·신뢰도** — 공공 정보 서비스는 99% 이상 수준 요구, 학습 데이터 확보 계획 필요
7. **효과성을 구체적으로** — 사고 예방, 대응력 향상, 업무 감소 등 측정 가능한 효과
8. **사업화·지속 가능성** — 귀찮음 대행 수수료, 후원 수수료, 지자체 업무 절감 대가, 유사 서비스 연계(단, 아이디어 유출 주의)
9. **발표 전달력** — 3분 안에 문제→해결→차별점→검증이 톡톡 전달되게. 동작하는 시연이 임팩트 큼

## 4. 산불 대응 AI(현장 지휘 의사결정 지원) 팀 관점 시사점

홍수 대응 의사결정 팀(①)이 받은 피드백이 구조적으로 가장 비슷합니다.

- 산불 대응 단계·지휘 체계는 **산림청 지침·매뉴얼로 규격화**돼 있음 → 서비스 흐름이 그 기준과 맞는지 근거 제시
- **최종 판단·책임은 현장 지휘관**에게 있다는 전제를 명확히, AI는 판단 근거 제공·지원 역할로 포지셔닝
- 산림청 등 기존 **산불 확산 예측 시스템과의 차이**를 먼저 정리하고 한 가지에 뾰족하게
- 정덕우 멘토가 **산림청 산불 진화 헬기 조종사·운영 경력**이 있으니 현장 흐름 검증·실무자 연결을 요청해볼 만함
- 과거 산불 사례 재구성·시뮬레이션은 홍수 팀에서 **차별점으로 긍정 평가**받은 요소
